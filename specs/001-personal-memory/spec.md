# Feature Specification — 一期个人记忆中心 v0.1

**Feature directory** `specs/001-personal-memory`

**Created** 2026-11-12

**Status** Implemented and validated in an isolated macOS environment

**Input** 用户确认一期 v0.1，按 M1–M4 连续推进。Codex 规划与功能测试，dsh 并行开发，Claude 独立审查，使用已配置的经济型第三方模型。

## User Scenarios & Testing

### User Story 1 - 跨工具立即共享当前要求 (Priority P1)

用户在一个工具声明偏好，另一个工具开始相关任务时自动获得同一要求及来源。

**Why this priority** 消除换工具后反复交代背景。

**Independent Test** 通过两个 Harness 的真实 hook 或插件入口完成声明、自动召回及纠正。

**Acceptance Scenarios**

1. 已接入两个工具，在 A 声明使用 SQLite，B 的任务开始回调获得带来源的事实。
2. 对同一事实声明纠正，B 下一次召回获得新版本，旧版本仍可追溯。
3. 切换项目后，相关记忆仍可检索，条件不匹配的事实不会误用。
4. 模型离线时，带事实键或纠正目标的声明立即生效，经历采集与关键词检索可用。

### User Story 2 - 归集历史并解释召回 (Priority P2)

用户导入已有长期记忆和会话，查看覆盖率及注入记录。

**Why this priority** 历史输入与持续采集共同形成可用记忆。

**Independent Test** 导入包含三个 Harness 事件及已注入段落的固定历史，再重复导入。

**Acceptance Scenarios**

1. 重复导入不增加同一事件，来源、解析器版本、游标及跳过原因可查。
2. 已注入内容再次采集时只记引用，同源复述十次仍只有一个独立证据。
3. 相同会话、任务与上下文中未改变的版本只注入一次，修订或上下文压缩后可以再注入。
4. Worker 暂停、失败后恢复会追赶，未处理项可见。

### User Story 3 - 自主治理、纠正与隐私遗忘 (Priority P3)

系统依据来源、证据和时间自主沉淀记忆，用户可声明、查看理由及遗忘。

**Why this priority** 维持当前事实正确性与可审计性。

**Independent Test** 以真实服务执行独立印证、低信任隔离、版本冲突、派生失效、遗忘与恢复。

**Acceptance Scenarios**

1. 推断获得两个独立来源，或经过 72 小时且置信度至少 0.8 无冲突，自动晋升并记录依据。
2. 网页或工具文本夹带规则时隔离，可信验证记录保留命令和结果来源。
3. 基于同一旧版本的并发纠正只有一个成功，另一个收到可见的版本冲突。
4. 纠正或遗忘使受影响派生物停止返回，有其他有效来源的派生物排队重算。
5. 备份恢复保留来源、版本、台账及游标，已遗忘内容被删除记录阻止复活。

### User Story 4 - 本地语义检索与可操作管理台 (Priority P4)

用户浏览真实记忆和台账，安装本地模型并开启中文语义检索。

**Why this priority** 支持换措辞召回和日常自助管理。

**Independent Test** 真实本地模型完成安装健康检查、中文换措辞检索及语义开关，管理台完成声明和详情检查。

**Acceptance Scenarios**

1. 启用语义会补建存量向量，关闭后保留向量并继续关键词检索。
2. 安装与修复展示真实进度，失败可重试，模型不可用时界面显示降级。
3. 七个页面均使用真实数据，声明生成版本，详情可查看来源和仲裁理由。
4. 375px 页面不溢出，键盘可打开详情、关闭并归还焦点，减少动效设置有效。

### Edge Cases

- 晚到旧观察依据发生时间进入历史，条件不同的事实可并存。
- 同一操作重试使用相同事件身份，不同时间的相同文本保留为不同事件。
- 无匹配结果时返回空，预算不足时省略整条记忆。
- 私密条目在云端目标的搜索、召回和证据展开中被排除。
- 原始文本中的凭据在数据库、证据和失败日志中保持脱敏。
- 损坏历史文件独立报告，不阻断其他文件导入。

## Requirements

### Functional Requirements

- **FR-001** 统一存储个人记忆，项目仅为来源与排序线索。
- **FR-002** 持久化事件、来源、版本、条件、发生和接收时间、任务及游标。
- **FR-003** 事件身份去重，事件与后台任务原子接收。
- **FR-004** 提供声明与显式纠正，版本冲突可见，保留历史。
- **FR-005** 提供当前事实、中文关键词和可选语义检索及来源展开。
- **FR-006** 在预算内自动召回，按会话、任务、上下文及版本避免重复注入。
- **FR-007** 支持 Claude Code、Codex、DSH 的自动回调、MCP 主动通路和历史归集，准确报告部分接入。
- **FR-008** 导入有清单、覆盖率、游标、解析器版本及错误原因，支持压缩历史。
- **FR-009** 根据 T1–T4 来源分类、独立证据和观察期自主晋升或隔离。
- **FR-010** 每次治理决定记录理由、证据、策略及模型版本，冲突无法裁决时展示分歧。
- **FR-011** 纠正沿来源关系失效派生物并清理派生索引。
- **FR-012** 遗忘清除正文、证据及派生内容，保留无正文删除记录，恢复时重放。
- **FR-013** 模型故障时采集与关键词读取可用，任务保留并自动重试。
- **FR-014** 入口脱敏、低信任规则隔离、私密内容限制本地上下文，记忆包标明参考信息。
- **FR-015** 自动准备本地运行时和固定模型，安装修复有真实状态，升级显式执行。
- **FR-016** 提供语义开关、存量回填及可重建索引。
- **FR-017** 提供总览、记忆库、星图、注入台账、历史导入、来源和设置七页管理台。
- **FR-018** 提供初始化、启动、自检、接入、导入、声明、召回、遗忘、备份恢复及运行时管理命令。
- **FR-019** 提供在线一致性备份和系统服务注册，数据与运行时分离。
- **FR-020** 每日整理及每周低重要性降权任务在后台执行，失败可追踪，不阻塞交互。

### Key Entities

- Event 是带稳定身份、来源类型、时间及敏感级的原始输入。
- Memory 与 Revision 表示主张当前状态及可追溯版本。
- Source 表示独立证据根及派生关系。
- Arbitration 是自主决策及其证据与理由。
- Injection 是某会话回合实际获得的版本与成本。
- Job、ImportCursor 与 Tombstone 分别表示后台进度、历史覆盖及隐私删除事实。

## Success Criteria

### Measurable Outcomes

- **SC-001** 原一期文档列出的 16 个黄金用例均有独立执行结果，两个真实 Harness 完成自动共享。
- **SC-002** 模型断开期间，已接受事件和带明确目标的声明零丢失，关键词检索继续返回结果。
- **SC-003** 重复导入、同源复述、版本并发、纠正、遗忘和恢复的功能检查全部通过。
- **SC-004** 真实本地模型在至少五组中文改写查询中命中对应经历，记录关键词与混合结果及召回耗时。
- **SC-005** 七页管理台显示真实状态，桌面与 375px 核心操作、键盘和减少动效检查通过。
- **SC-006** 独立代码审查的阻断性发现处理完毕，记录实际审查覆盖、测试命令与未测项。

## Assumptions

- 用户已确认一期 M1–M4 的实施范围，多电脑同步按既有二期设计后续推进。
- 声明可附事实键或 memory_id。自由文本先以独立 T1 事实立即可读，后台模型再判断关联和冲突。
- T2 只接受采集器明确构造的验证结果，普通工具正文按 T4 处理。
- 晋升以治理正文的两个来源或 72h/0.8 规则为准，T1 决定当前工作要求。
- 隐私遗忘优先清除正文与证据，追加写原则适用于其余普通生命周期操作。
- 首次安装和修复使用固定版本，runtime update 显式刷新版本。语义安装验收归 M4。
- 本轮开发在隔离数据目录与配置根联调，接入命令支持应用到用户环境。
