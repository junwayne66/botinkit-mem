# CLI 与发布契约

## 用户命令

| 命令 | 合同行为 |
|---|---|
| `bmem update --check` | 验证发行目录并报告当前构建、可用稳定版和兼容性。只可写本地可信元数据缓存；服务和活动数据保持原状态 |
| `bmem update` | 对受管安装执行更新。按系统与 ABI 选取已安装架构的最新兼容稳定目标，并要求有效迁移边。已在当前最新目标时返回 `up_to_date`；最新发布缺少兼容性或迁移边时报告当前可用目标与升级路径。跨架构接管经显式选择 |
| `bmem update status` | 读安装和操作记录，显示阶段、版本、维护及恢复状态。`recovery_cleanup` 为 `retained`、`pending` 或 `complete`。服务停机时仍可用，通用 `bmem doctor` 显示摘要 |
| `bmem update resume` | 以同一安装和操作 ID 对账。中断发生在放行意图提交前时恢复旧状态，提交后继续发布新安装。已到终态时可重试删除该事务的 SQLite 恢复点，再返回现有操作结果。程序路径不可用或旧程序没有该命令时，使用可信独立安装器执行 `update resume` |
| `bmem update rollback` | 依据实际状态与兼容矩阵执行本机恢复。已可能开放写入时只允许旧程序接管当前兼容数据。兼容失败时报告 `repair_required` |
| `bmem --json update …` | 标准输出单个 JSON。字段为 `operation_id`、`status`、`phase`、`installed_version`、`installed_build`、`target_version`、`target_build`、`instance_id`、`error_code`、`next_command`。无操作的项可为 null |

| 退出码 | 含义 |
|---|---|
| `0` | 成功或无须切换；检查模式用 `status` 区分 `update_available` 与 `up_to_date` |
| `10` | Windows 已完成交接给同卷助手，结果以 `bmem update status` 的终态为准 |
| `20` | 维护冲突、占用超时、阻止开启下一次事务的待清理恢复点、明确可重试的网络或 I/O 错误 |
| `21` | 未通过签名、渠道、目标平台或数据兼容性验收，或安装由其他管理器负责 |
| `22` | 更新未达到放行条件，旧服务已经恢复 |
| `23` | 保持维护，需要可信修复入口；禁止自动恢复历史数据 |

支持维护协议的服务对普通写请求返回 `503 update_in_progress` 与 `Retry-After`，重试使用原幂等键。旧版首次接管期间可能短时断连。故障前已受理的记录需持久保存。未受理的采集可由具备读取权限的原生历史按原事件 ID 补录；宿主无法重试或回填时，安装器在停写前提示暂停需要记录的操作。

## 首次接管与发行验证

- 发行内容含平台专用首装入口、独立修复入口、签名更新目标、发布说明与验证记录。先通过可信入口核验初始根或发布者身份，接管器才能运行。macOS/Windows 核对本机签名、公证条件与公布的签名身份；Linux 首次从官方仓库取得可信 root，并通过独立可信来源安装的 TUF 验证器核对安装器目标签名、长度和摘要。相同入口用于从程序文件缺失或损坏的状态进入恢复。
- 官方接管命令设计为已验证的 `bmem-installer --adopt --binary <绝对路径> --home <原根>`。先显示当前命令匹配、程序真实路径与实例，接管已有安装保留已确认入口。路径被第三方包管理器拥有，或指向无法证明的实例时停止。
- 稳定制品身份以签名目标、摘要、SemVer 与 build ID 共同决定。已发布版本优先级单调；撤下目标发布更高元数据版本，已接受的元数据或版本高水位持续保存。同版本制品变更须发布新版本。
- TUF 沿用 root、targets、snapshot、timestamp 协议。渠道站点存放元数据与小体积的 TUF 目标目录。目录为每个平台声明兼容范围、不可变 Release 资产 URL、长度及 SHA-256。更新器从已验证目录选择制品，按签名目录检查下载的实际字节后才解包并尝试执行。归档只接受声明的原生程序及必要清单。下载只访问官方 HTTPS 渠道及指定的 Release 下载端，诊断日志按 FR-008 保留操作字段。
