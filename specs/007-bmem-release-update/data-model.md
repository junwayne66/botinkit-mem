# 安装、发布与恢复记录

| 记录 | 必需字段与用途 |
|---|---|
| 安装登记（用户私有） | `install_id`、受管或外部类型、程序真实路径、命令别名、构建 ID 和摘要、渠道、数据根及 `instance_id`、已识别的宿主和启动器路径。路径验证使用解析后的本地绝对路径及现有定位登记。程序目录与数据目录允许在不同本地卷 |
| TUF 已信任元数据 | 初始 root 指纹、当前可信 root、上次接受的各角色版本。每次读取校验有效期和更新序号，持久信任数据独立于可清理下载缓存。渠道稳定目标是带 TUF 签名的目标目录。另存每渠道已成功提交安装的最高发行版本，兼容的本机程序回切保留这两层记录 |
| 发行目标目录 | 稳定版 SemVer、构建 ID、commit、Rust triple、最低 OS/ABI、目标长度和 SHA-256、声明库的读写 epoch 区间、可证明迁移来源、最低更新器协议、发布说明位置。两库及其它受迁移格式的兼容边界须明确区分 |
| 升级事务 | `operation_id`、来源/目标构建和摘要、实际入口、实例、OS 启动器原状态、恢复点、预期 epoch、当前/待执行阶段、持久提交标记、最后错误。捕获停写和恢复时间，供每个来源计算补录水位。日志由用户私有原子写入，同实例状态查询可离线工作 |
| 专用恢复点 | SQLite Backup API 获取的原权威库和设置库、迁移触碰的受管对象清单、原入口及摘要、权威变更水位、撤回水位、完整性检查、系统启动器原状态。只存本机私有目录。与通用数据导出归档分开 |
| 运行时验证 | 实际可执行构建、CLI/HTTP 协议兼容级别、服务确认的 `instance_id`、权威和设置库兼容标记、Web build、FTS 结果、宿主连接代际与测试结果 |

## 中断恢复

| 断点 | 对账与恢复 |
|---|---|
| 已暂存，尚未停写 | 按同一操作 ID 验证下载与目标摘要后重试，或清理本次暂存 |
| 已停止并备份，未完成替换 | 按实际程序摘要、库水位和恢复点核对；原位恢复或继续同一操作 |
| 已替换或迁移，未持久提交写入放行 | 恢复上一程序；若持久数据发生变更，先验证同实例恢复点，再恢复全部受影响组件。任何一道检验失败时保持维护态 |
| 写入放行意图已持久化 | 按可能已接受新写入处理。禁止自动还原旧数据映像。兼容时只回切程序，否则从当前库前向修复 |
| 账本或被替换文件不可用 | 可信的独立修复入口对活动根、锁、文件摘要及水位再核对。仅在一致状态下解除维护 |

每个切换写前持久化意图，按实际摘要和 `epoch` 对账。事务到达 `published` 或 `rolled_back` 后，更新器在持有实例和安装锁时清理账本 ID 对应的 SQLite 恢复点，清理失败保留可重试状态。未完成事务继续保留其恢复点。过往目录缺少可核对的事务账本时予以保留。上一已验证程序位于独立的安装目录，供兼容回切使用。恢复哪一版当前值以提交水位和撤回证据为准。[Rust 目录删除行为](https://doc.rust-lang.org/std/fs/fn.remove_dir_all.html)

## 连续性队列的写入兼容性

权威库写入世代从 2 升至 3。本次迁移让 `failed` 表示终态，并将待自动重试的作业放在 `retrying`。旧版会自动领取 `failed`，因此由写入围栏拒绝旧进程启动。迁移保留旧作业 ID、累计领取次数和最后错误。旧 `failed` 作业进入 `retrying`，以新预算开始计算，因为历史累计次数混合了模型故障和单条失败。提交前可原位恢复旧程序与旧库。提交后保留当前库，使用兼容候选继续运行或签名向前修复。[状态迁移](../../src/v2/bmem/src/ingestion.rs) · [写入围栏](../../src/v2/bmem/src/storage_epoch.rs)
