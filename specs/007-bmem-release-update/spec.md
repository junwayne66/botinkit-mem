# 功能规格 · bmem 正式发布与原位升级

日期 2026-11-27。用户从现有 bmem 安装升级到正式发布版，之后运行 `bmem update` 即可安装当前稳定渠道的最新兼容版本。方案延续 V2 的桌面及本机服务边界。[CLI 与平台设计](../../docs/v2/technical/cli-and-platform.md)

## 用户场景与验收

| 故事 | 优先级 | 验收场景 |
|---|---|---|
| US1 旧安装首次接管 | P1 | 给定缺少 `update` 子命令的 0.2.0 和已有 CLI、登录启动项、Hook/MCP，执行一次经过验证的官方安装器接管。重开终端及两款宿主后，均连接同一旧实例并使用新构建。存在多个候选安装或不同实例时，给出准确定位与下一步 |
| US2 日常升级 | P1 | 对受管安装运行 `bmem update`。同一机器选中正确系统、架构的稳定制品，完成校验与服务健康检查后报告成功。已是最新时返回当前版本，重复执行无额外切换。检查模式可在服务运行时查看目标和兼容性 |
| US3 安全失败与恢复 | P1 | 在下载、停写、替换、迁移、健康检查及放行阶段分别注入故障。切换前保留可用旧服务，放写前可恢复同一个实例，放写后的任何恢复保留更正、撤回、待办与导入游标。可从终端查询事务状态 |
| US4 维护者发布 | P1 | 从一个确定提交生成平台制品，经过各平台安装/升级/故障测试及签名后发布。稳定渠道只在资产齐备、可下载且验证通过后推进。撤下目标后已安装客户端收到正确状态或更高版本的修复 |

## 边界场景

| 输入 | 用户可观察行为 |
|---|---|
| 离线、证书或签名异常、找不到兼容制品、空间不足 | 显示可区分的原因。现有安装与已确认写入继续可用 |
| 第三方包管理器、路径不唯一、实例无法证明 | 报告实际命令与登记来源。通过对应包管理器处理，或在用户明确选择后接管指定的自有安装 |
| 服务初始停止、无用户服务管理器、宿主仍占用可执行文件 | 恢复原启动策略。占用超时列出相关 bmem 进程或宿主连接，并给出重试方式 |
| 迁移后进程退出、断电、磁盘写入失败 | 查询获得上一次阶段与恢复条件。未完成事务只允许一次恢复；运行态不出现两台写服务 |
| 新服务已开放写入后发现故障 | 可证明旧版兼容当前数据的情况下只回切程序。格式不兼容时保留当前库并使用更高兼容版本修复 |

## 功能需求

- **FR-001** 提供官方首次安装与经验证的现有安装接管。记录命令入口、调用方路径、用户级启动项与业务实例身份。
- **FR-002** 提供稳定渠道的显式检查、升级及状态查询。选用满足平台、更新器与业务库兼容范围的发布版本。
- **FR-003** 校验可信发布方、版本元数据和制品完整性。发布中途及校验未完成期间旧服务继续运行。
- **FR-004** 切换期间最多一个写入者。已受理的业务事件及后台工作可按原幂等键或持久游标续跑。保留程序、设置和必要数据的恢复点。
- **FR-005** 安装成功由实际服务和宿主入口验证；命令、服务、内嵌 Web、Hook 与 MCP 应使用预期构建及原业务实例。
- **FR-006** 恢复执行依据持久阶段与业务写入状态，保留真实恢复结果。宿主和用户启动设置只能按原登记恢复或在明确选择后修复。
- **FR-007** 每个稳定版本有唯一版本与构建身份。发布记录必须包含兼容范围、制品校验信息、实际平台证据和撤回处置。
- **FR-008** 升级过程中工作区数据、源凭据、授权和模型绑定留在本机。日志只记录恢复所需的操作 ID、版本、阶段与错误类别。

## 采集与提炼连续性

以下补充 P0 运行保障。实现及回归状态见 [T024–T026](tasks.md#采集与提炼连续性) 和[验收报告](continuity-validation-2026-11-27.md)。

| 用户关心的情形 | 升级前行为 | 修改要求 |
|---|---|---|
| 升级会不会打断采集与提炼 | 下载和验签时旧服务继续运行。切换时服务停写、暂停领取提炼和历史作业，实时 Hook 可能收到维护错误，旧宿主也可能短时断开。已经入库的事件、作业及游标随 SQLite 保留。持久作业可以从原状态和租约续跑。已开启且仍获准的历史来源可以增量追赶。实时 Hook 本身没有把维护期未提交的事件普遍留存的机制 | **FR-009** 升级前提示预计停写影响，复用原幂等键、事件标识和最后提交的游标。升级成功或回退后自动续跑已受理作业，恢复仍获准、仍可读的来源历史或由发送端重投未确认事件。逐来源区分已追平、仍补录和需用户操作。原始事件不可回读、发送端不能重投或缺少授权时显示覆盖缺口；保留原有采集、提炼授权和撤回限制 |
| 提炼模型不可用 | 已获准的采集仍可入库并持久排队。遇到调用失败，单条作业显示原因并按退避时间再次尝试，可领取的作业在模型恢复后继续。后台作业页面可查看单条错误，缺少统一的模型故障提醒和明确的等待模型状态 | **FR-010** 发现模型断连、超时、限流或明确的服务故障时，提示「提炼暂停，采集继续」，展示影响范围、积压数量、最老等待时间、最后成功处理时间、故障原因和下一次探测时间。待办持久化为「等待模型」。按退避探测同一已授权路线，探测成功后自动续跑等待项并清除提醒。认证或配置问题显示修复指引；模型路线更换仍须遵守现有授权 |
| 单条数据反复失败 | 作业可以自动重试，存在 `bmem job retry <job_id>` 和工作台「重新排队」入口。当前失败状态仍可被自动领取，没有每轮重试上限，也没有独立的失败队列边界 | **FR-011** 首次处理失败后，最多自动重试三次；三次仍失败进入失败队列并停止自动领取。明确不可重试的单条错误可直接进入失败队列。保留原作业和事件版本、尝试历史、错误码及时间。所有者可按原作业重新排队，启动一轮新的重试预算。自动领取及重新排队均复核当前权限和事件有效性，仍被撤回的输入禁止重放 |
| 许多数据接连失败 | 当前按单条作业记录失败和退避；提炼 worker 会领取其他可处理作业，没有根据共同故障暂停新作业的判断 | **FR-012** 确定的服务级故障立即暂停受影响的提炼路线。对于疑似共同故障，初步按同一路线 10 分钟内连续 3 个不同作业出现同类错误进入探测，探测失败后暂停继续领取。模型恢复后先放行少量等待作业，通过后恢复正常。授权采集与持久入队、手动声明、精确与词法查询继续可用。单条坏数据、撤回、用户暂停或处理成功但零候选不得触发系统故障 |

单条作业的自动重试复用现有退避策略。共享模型故障造成的等待以及升级中断造成的租约恢复，均不计入三次重试。自动恢复处理等待项。失败队列沿所有者重新排队入口处理。状态、提醒和诊断仅记录所需的计数、时间及错误分类。共同故障探测的初始判定值为 10 分钟内连续三个不同作业出现同类错误。

实现见[升级账本](../../src/v2/bmem/src/update/mod.rs)、[历史增量恢复](../../src/v2/bmem/src/history.rs)、[作业领取及重排](../../src/v2/bmem/src/ingestion.rs)、[提炼路线状态](../../src/v2/bmem/src/extraction.rs)和[工作台作业状态](../../src/v2/web/app.js)。

## 成功标准

- **SC-001** macOS、Linux、Windows 的 6 个目标各通过普通用户首次安装、0.2.0 接管、连续升级和已有最新版本四个场景。
- **SC-002** 对关键阶段进行故障注入。任一测试中已确认业务写入丢失数为 0，旧撤回复活数为 0，并发权威写入者最多 1 个。
- **SC-003** 两款真实宿主在升级前后实测 Hook 和 MCP 随重新连接获取预期构建的响应。终端、登录启动项和宿主指向同一实例。
- **SC-004** 新版本兼容性验收复跑 006 冻结的 134 条用例与 652 条断言，并独立保存正式制品的跨平台升级和中断恢复证据。
- **SC-005** 记录每个目标在干净安装、典型既有库和大库上的停写时长、总时长、回退时长及额外磁盘用量。稳定发布按版本说明公开实测范围。

## 关键实体与假设

安装登记、签名发布、稳定渠道目标、升级事务、同实例恢复点、写入兼容级别、构建身份、宿主及启动器匹配结果。

现阶段按单机单活动数据根、普通用户安装及公开稳定渠道设计。版本示例使用 0.3.0。已知本轮要迁移的是旧 Rust V2 安装；更早的非 V2 数据仍进入项目既有迁移入口，再执行本规格。系统软件包用户按对应发布渠道升级。
