# Feature Specification · 持续更新的事实与真实记忆星图

**Feature Branch** `main`

**Created** 2026-11-14

**Status** 两切片均已本地发布，隔离验证、独立复审与运行校验通过

**Input** 用户要求按事实发生或明确生效时间更新同一主体的事实，保留历史和出处，建设可查看证据的真实关系星图，并基于真实积压与有效吞吐评估现有架构。循环修复已单独审查、部署。后续本地提交和部署经过独立 review，platform-admin 享有最高资源优先级。

## User Scenarios & Testing

### User Story 1 · 使用当前有效事实 (Priority P1)

用户更改事实后，召回采用较新的可信事实。晚导入的历史资料可追溯，当前事实保持正确。

**Why this priority** 用户明确说明事实会持续更新，冲突应以较新事实为主。

**Independent Test** 从公开声明和候选处理入口依次提供不同事实时间、导入顺序、条件和可信度，检查当前召回及历史记录。

**Acceptance Scenarios**

1. Given 同一主体、事实与适用条件，When 可信度相近的新事实生效时间更晚，Then 当前正文更新，历史正文、事实时间及出处可查看。
2. Given 已有较新事实，When 旧资料晚导入或模型指定该记忆更新，Then 保留旧资料的事件与审计记录，当前正文和事实时间保持正确。
3. Given 用户明确声明，When 较新的低置信助手推断与它冲突，Then 推断进入待确认记录，当前明确事实继续可用。
4. Given 同一事实有不同适用条件，When 更新其中一个分支，Then 另一分支仍可独立召回。
5. Given 同值再次确认，When 确认时间较晚且随后收到中间时间的相反资料，Then 最新确认水位阻止旧资料反向覆盖。
6. Given 同范围存在多个争议事实，When 较新的可信事实解决这些旧争议，Then 已解决的旧争议退出当前检索和召回，正文、版本、来源与取代依据继续可追溯。

### User Story 2 · 查看真实关系和替代历史 (Priority P1)

用户在记忆星图查看真实派生、共同来源和版本替代，选择节点或连线可以追溯详细记忆和证据。

**Why this priority** 当前首页截取的节点可能没有关系，纠正采用同一记忆的多个修订，现有图谱未呈现这些历史。

**Independent Test** 使用有派生、共享证据、修订及独立节点的受控数据，通过真实图谱接口和浏览器验证连线、详情、筛选与刷新。

**Acceptance Scenarios**

1. Given 两条记忆共享持久化来源，When 查看星图，Then 显示具有实际来源依据的关系，能打开来源事件。
2. Given 一条记忆被修订，When 查看其替代关系，Then 可以区分当前与历史版本，查看修订正文和时间。
3. Given 显式派生包含多个父级，When 查看派生连线，Then 每个真实父级都有对应证据。
4. Given 新建关系或修改筛选，When 重新进入或刷新星图，Then 使用最新数据，筛选后的范围决定显示节点。
5. Given 资料中没有关系，When 展示这些节点，Then 如实显示独立节点和关系数量。

### User Story 3 · 获得可验证的运行评估 (Priority P2)

用户了解哪些积压需要模型处理、哪些已作为引用或工具证据保存，以及实际生成当前记忆的速度。

**Why this priority** 完成的任务可能只完成证据归档，需要区分业务进度和任务计数。

**Independent Test** 对现有代码和只读任务统计交叉核对分类规则，使用隔离数据验证活动依赖和历史来源的完整追溯。

**Acceptance Scenarios**

1. Given 包含历史、重算和索引任务的队列，When 汇报进度，Then 分别列出任务类型、来源、历史标记、归档跳过和记忆写入。
2. Given 自定义来源根的多级派生链，When 上游事实更新，Then 有效间接依赖能够被完整识别，遗忘仍追溯历史来源。
3. Given 独立负载测量正在运行，When 实施本轮功能，Then 使用隔离验证和现有资源配置，测量由指定观察方收集。

### Edge Cases

- 相同事实时间的相反内容无法仅靠导入先后分辨，保留待确认冲突，用户显式版本纠正可消歧。
- 旧数据库和旧备份尚无独立事实生效时间时，从已记录的事实或来源事件时间读取兼容值。
- 外部规则继续隔离，隐私资料在本机界面与云端目标的可见范围遵循既有边界。
- 来源已失效、事件已被遗忘、历史版本已清除时，关系详情准确标记可用性。
- 节点展示上限不会以虚构连线补齐图形，完整修订历史在详情中可查。

## Requirements

### Functional Requirements

- **FR-001** 事实身份使用包含主体含义的稳定事实键和精确适用条件，模型指定目标也要遵守分支边界。
- **FR-002** 声明和模型候选可表达事实生效时间，缺省采用原事件发生时间，原始事件时间与采集时间分别保留。
- **FR-003** 可信度相近的同一事实采用较新的事实时间，已解决的同范围旧争议退出当前检索和召回，保留旧正文、版本、来源和决策历史。
- **FR-004** 各更新入口统一阻止晚到旧事实反向覆盖，相反旧资料不得被计为当前正文的支持证据。
- **FR-005** 同值确认维护时间水位，同时间的未消歧冲突进入待确认状态。
- **FR-006** 低置信推断不能自动覆盖用户明确声明，外部规则继续遵循隔离和确认边界。
- **FR-007** 当前事实及各修订可查看事实时间，已有数据与备份可兼容读取。
- **FR-008** 星图关系来自持久化派生记录、真实来源和修订替代，携带可追溯证据及有效性信息。
- **FR-009** 节点和连线可打开详情、修订及来源事件，隐私筛选覆盖相关端点。
- **FR-010** 星图在筛选后选择有限节点，优先保留真实关系端点，重新进入或用户刷新可获得最新关系。
- **FR-011** 有效与历史依赖的多级闭包正确，活动失效传播和隐私遗忘使用各自所需的来源范围。
- **FR-012** 运行报告区分原始完成计数、归档跳过、普通蒸馏和实际写入，功能实现服从资源优先级及已指定的独立测量安排。

### Key Entities

- **事实** 包含主体语义的事实键、适用条件、当前内容、可信度和事实时间。
- **修订** 某条事实的历史正文、事实时间、前一版本和来源事件。
- **来源关系** 支持来源、派生依据和来源失效时间，既有持久化记录是权威。
- **星图关系** 来源、派生和替代关系的展示，引用实际权威记录。
- **运行进度** 按任务类型和来源统计的工作量及真实记忆写入结果。

## Success Criteria

### Measurable Outcomes

- **SC-001** 新旧资料两种到达顺序、跨条件输入、显式目标和低可信推断回归全部通过，当前事实及历史时间可核验。
- **SC-002** 浏览器验收可分别打开派生、来源和版本替代的证据，受控独立节点不产生关系。
- **SC-003** 首页与完整星图显示的节点和关系计数对应实际显示内容，筛选和重新进入后的关系与最新数据一致。
- **SC-004** 队列报告能说明完成任务的实际构成，循环修复、依赖闭包缺陷与模型吞吐分别有代码或运行证据。

## Assumptions

- T1明确声明与T2验证结果视为可信度相近，T3推断继续采用既有确认边界，T4外部规则继续隔离。
- 事实键表达主体与事实范围，项目标签描述出处。不同适用条件以现有条件对象区分。
- 星图可展示最近替代关系，完整修订历史复用详情入口。
- 当前使用单机服务、既有存储与界面。业务调度、任务频率和并发度由用户在负载测量后决定。
- 本轮验证使用隔离数据，独立评审后进行本地提交与部署。
