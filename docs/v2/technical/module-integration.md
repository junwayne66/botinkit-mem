# 六域并行开发与集成

第一个可交付切片是「在 CLI 追加声明，网页读到同一修订，获准的另一款助手在下一次任务实际装入」。第二个切片让普通对话与工具回执自动生成有出处的经历。下面给出两个切片公用的代码边界、数据所有者、接缝和集成证据。P0 手工可用的声明、检索和授权必须能在模型离线时工作。[首发验收场景](../product/acceptance.md)

## 代码怎样放

建议一个 Cargo workspace、三个 crate，最终只分发一个 `bmem` 程序。六个领域是 Rust 模块，按事务使用同一 SQLite 实例。以下是拟建源码布局，每行右侧为维护范围。[技术选型](runtime-route.md) · [Cargo workspace](https://doc.rust-lang.org/cargo/reference/workspaces.html)

```text
Cargo.toml
crates/bmem-contracts/src/        公共 ID、新类型、消息、枚举、能力描述符与序列化
crates/bmem-core/src/app/         应用命令入口、身份上下文、跨域事务编排
crates/bmem-core/src/storage/     建库、SQLite 事务执行器、按依赖装配迁移、对象文件操作
crates/bmem-core/src/ingestion/   D1 接入与采集
crates/bmem-core/src/authority/   D2 证据与权威写入
crates/bmem-core/src/extraction/  D3 提炼与巩固
crates/bmem-core/src/retrieval/   D4 检索与上下文
crates/bmem-core/src/feedback/    D5 反馈与学习
crates/bmem-core/src/operations/  D6 运营与治理
crates/bmem/src/                  main、CLI/HTTP/MCP 适配、程序组装及三平台实现
crates/bmem/web/                  随制品嵌入的 Web 资源与动作绑定
crates/bmem/tests/                通过真实 CLI、HTTP、宿主协议运行的跨域验收
```

依赖方向为 `bmem → bmem-core → bmem-contracts`；入口也可直接使用公共消息。`contracts` 只依赖类型与序列化。各域目录包含自己的命令/查询实现、SQL、该域的迁移文件和邻近单元测试；公共事务执行器装配这些迁移。提供方调用、宿主文件与 OS 启动器等副作用通过域定义的窄接口注入，程序入口选择具体实现。一个域需要另一个域的授权读取或写入时调用公开端口，不直接更新对方的表。工程实现时每个切片的规格、计划和工作项沿用 `specs/<feature>/`；此页用于划分团队工作面和验收边界。

## 责任与可并行的首个产物

| 维护范围 | 可以独立开工的产物 | 合流时对接 |
|---|---|---|
| 应用入口、平台、CLI/Web | 描述符、命令解析与表单绑定、`~/.bmem` 发现、用户会话、配置比较修订，先以 `config.patch` 做双向改值 | 使用真实本地 HTTP 及 D6 设置服务。平台小组在 macOS、Windows、Linux 分别验证签名、初始化、服务启动与更新。[命令目录](command-catalog.md) · [扩展接口](extension-contract.md) |
| [D1 接入与采集 · M01–03](domains/ingestion.md) | Claude Code/Codex 原生消息到规范信封的样本、重复页和断点游标、同仓异工件的任务锚点 | 调 D2 接受事件，取回源版本及持久回执。调用 D4 装入、向 D5 提交宿主实际观察 |
| [D2 证据与权威写入 · M04–06](domains/authority.md) | 在临时 SQLite 实例跑通证据、明确声明、逐维裁决和当前授权读；覆盖原文与共享值权限不同 | 给 D1 单一页提交边界，给 D3 提案提交端口，给 D4/D5/D6 当前授权和稳定引用 |
| [D3 提炼与巩固 · M07–09](domains/extraction.md) | 用固定的已授权窗口及结构化候选样本验证来源定位、计划/执行区分、零候选与中断；模型探针可并行开发 | 从持久待办取得输入，模型在事务外运行。由 D2 复核并一次提交裁决与任务状态；声明切片通过后接真实提炼 |
| [D4 检索与上下文 · M10–12](domains/retrieval.md) | 以固定修订做 FTS5 建索引、获准窗口补读、两套预算、三档序列化。向量关闭时测试零嵌入调用 | 生产候选用 D2 最终授权读取；声明直读可先合流。将实际提供清单交 D5，保留独立的宿主回执 |
| [D5 反馈与学习 · M13–15](domains/feedback.md) | 验证一次投递、多次尝试、缺少宿主观察时的归因；建立合成断言和独立结果的评分入口 | 接 D4 投递与真实宿主绑定。P0 出具逐阶段验证结果；用途数据集、离线训练和策略发布按 P2 开放 |
| [D6 运营与治理 · M16–18](domains/operations.md) | 在隔离数据根跑操作单、清理进度、归档及恢复预览。给 CLI/Web 配置、诊断、作业与恢复的回读 | 调 D2 事务立即收窄权限；按 D1/D3/D4/D5 各自的引用表清理。恢复时执行合法/禁读对照，再开放服务 |

## 跨域消息与提交边界

所有带 `_id` 的公开标识由其所有者签发。依赖方保存返回值；只用受人工命名的夹具标签跨隔离测试比对。时间与时区、双时态、错误体、幂等作用域、单据状态见[服务契约](contracts.md)，数据关系见[权威表设计](authority.md)。

| 边界和输入 | 生产者交给消费者 | 提交及重放规则 |
|---|---|---|
| D1 → D2，接一页来源 | 已绑定的来源与账号、原生版本和 ID、角色、变更类型、发生时间、字段片段、前后游标、任务锚点 | 应用层只开一次写事务。D1 写去重映射/游标，D2 写来源版本、原件引用、必要待办及受理结果；到达提交点前不回成功。相同页重放返回原受理且不多派任务 |
| 所有者或 D1 → D2 → D4，声明 | 本人原话或可信的本人消息引用、范围/共享意图、可选纠正目标 → `statement_id`、逐维 `revision_id`、状态及 `change_seq` | 声明及依据同事务。D4 下个请求按当前授权和有效时间直读；无需等待索引消费、模型或批处理。任一已完成投递保留当时的修订 |
| D2 → D3 → D2，提炼 | 待办中的输入版本及任务、授权窗口、实际模型与模板 → 逐项定位的候选、预期事实修订、运行 ID | 模型调用前结束读事务。提交时核对授权、输入与当前事实，成功将全部裁决/无结果及作业终态一并写入。中断重放以同一来源、输入版本和处理版本定位已提交结果 |
| D2 → D4 → 客户端，检索 | 已提交修订及 `change_seq` → 投影 `applied_seq`，候选引用 → 可见修订、原文句柄、声明快照及任务证据包 | 后台可重建、停机或落后；真正补读与出站时检查当前授权和依据。给未知目的地只发可确认允许的字段。数据模式、平衡与高压缩用相同允许集合，关键事实须同等可核对 |
| D4 → D5，结果观察 | 实际提供的 `delivery_id`、`snapshot_id`、`package_id` 与修订；宿主另报实际模型调用/采用证据；验证器另报 `attempt_id` 和工件结果 | D4 写已提供的投递记录，D5 持有其后续观察与独立结果。重复观察幂等，缺观察明确未知。一次任务成功不会让整包事实都获得采用证明 |
| D6 → D2 → 各域，治理 | 明确目标、用途和预期版本、`preview_id` → `operation_id`、授权/撤回水位、受管位置 | 禁读与清理待办在同一短事务生效。各域在事务外清理自己的派生物，按位置回报单据；合法独立来源仍可读，外部已送出单列 |

队列就放在 SQLite。事务内写出变更和待办，领取操作只改作业状态；同一个后台循环按种类分派给域处理函数。消费端以「种类、目标、输入版本、策略版本」认领同一工作，投影额外持有自己的 `applied_seq`。领域负责人提交自己的 schema 与约束，集成负责人按外键和输入依赖登记迁移次序。每次合流都在空库完整建一次库，并从当前 V2 切片的库副本向前验证；现有 Python 库无需迁移。

## 共同回放与合流顺序

[溪桥接力夹具](interfaces/handoff-fixture.json)给出五条输入、三个合成接收范围和七个时点的八组断言。`label`、`route`、`support` 仅供测试驱动引用；驱动通过正常注册、授权和创建接口换取真实 ID，并把原始响应绑定回标签。`writer` 和 `reader` 是同任务获准的两个接收范围，`restricted` 仅可读共享声明。两条不同工件的工具输出刻意给出相反的入库结果，捕捉串任务误判。相同期望应覆盖三个压缩档，分别记录实际传入的证据与补读成本。

| 合流点 | 谁需交付什么 | 放行证据 |
|---|---|---|
| ① 公共契约、最小可启动程序 | 集成者先装配公开 DTO、描述符、错误码、空数据根与单写事务执行器。各域负责人可同时实现自己的端口、SQL 和夹具。CLI/Web 共同接入配置读写 | CLI 改值 → 浏览器回读相同修订，反向亦然；两端同时改旧版只有一方提交成功。服务重启后再读、默认向量零调用。[配置测试样例](interfaces/config-patch.example.json) |
| ② 声明切片优先 | D1、D2、D4、D5 接真实 Claude Code 与 Codex，D6 提供接收范围。D3 用固定输入独立测试，后台提炼不在此切片的关键路径 | 一个助手录入两个维度，在另一助手无关键词任务里核对实际装入，再只改开头。两端对照语言修订未变、开头已取代。真实宿主只能查或缺装入凭证时，记录缺口，不能将合成回执记为通过 |
| ③ 自动提炼、跨任务隔离与治理 | 上述切片通过后，D3 接真实已授权模型，D1 实际记录普通话语及工具回执，D4 给另一助手接手材料。D6 同时验收来源撤回与恢复 | 溪桥 `@3` 的解析通过、入库超时分别能补读，`@4` 的入库成功不能串入。提炼中间撤回时阻断提交，恢复旧库也不能复活撤回的原句。保存输入/候选/裁决/实际投递/结果的可追溯引用 |
| ④ 三端发行与质量验收 | 平台、检索与反馈团队在固定用例上复跑三系统、两宿主、三档；另测显式开启向量的路径。真实安装与平台启动可从①起并行准备 | 实测安装、升级与恢复，公布前台延迟、资源、磁盘总量、含重试的任务 token；准确率未达数据模式基线的任务继续用已验证表示。[性能放行条件](compression-and-performance.md) |

单域开发可用临时 SQLite 数据根、真实对象文件、确定的输入和录制响应验证端口。合流时走编译出的 CLI、浏览器的实际写请求和服务读回，核对同一个库的返回结果。建议未来 workspace 用 `cargo test -p bmem-core <域名>` 跑域内筛选（核对实际执行条数），用 `cargo test -p bmem --test cli_web_parity` 和 `cargo test -p bmem --test handoff_replay` 分别承载双入口与接力的集成场景。宿主和生成模型真实联调单独记录版本、权限、运行环境和实际观察。上述测试入口为实施目标。

## 本轮设计校验

- 对照冻结研究表和总览，六份分册的 M01–M18 编号、名称及归属逐一匹配。已复核 18 个模块的上下游和独立验收，重点交叉检查来源级遗忘的水位、同名模型换路由、配置重试与双入口恢复。仓库根运行 `shasum -a 256 -c docs/v2/research.sha256`，十项均匹配。
- 使用项目开发环境的 `jsonschema.Draft202012Validator` 校验动作描述符和设置输入/输出 Schema，六个配置请求及响应示例均通过。补测合法修改、错误类型、缺少 Web 或 CLI、直接写入授权/原始密钥、重放夹具中的引用等结构约束。V2 文档的本地链接与锚点可解析。
- 三平台签名制品、两端真实修改和崩溃重试、Claude Code/Codex 装入与提炼准确率均是后续实施验收。合成夹具与静态契约只能证明输入输出定义可以对接。
