# D4 · 检索与上下文

本域把授权修订交给一个具体接收者。M10 维护可重建的读索引，M11 按任务取得获准证据，M12 将声明和证据装成宿主可以处理的一次投递。D2 持有事实、授权、撤回与原文引用。D4 自己的写入限于投影、水位、包与投递清单。宿主装入后的观察交给 D5。[权威读取顺序](../authority.md) · [宿主 HTTP 契约](../contracts.md)

## M10 索引与关系投影

| 实现边界 | 约定 |
|---|---|
| 输入与调用方 | D2 事务待办提供已提交的 `change_seq`、受影响对象及输入版本。M10 按重建用途回读仍可保管的内容。D6 指定投影种类和目标水位发起重建 |
| 写入与输出 | 普通 SQLite FTS5 记录可检索片段的来源版本、片段 ID、原词频与扩展词字段。按授权域裁剪建索引的字段。关系投影保留两端的版本、谓词和依据引用。每个投影登记索引版本、授权域、分词或模型版本、输入水位、活动版本。对 M11 返回命中的修订／片段引用 |
| 分期 | P0 做精确键、FTS5、直接依据边。向量默认关闭，仅显式开启且模型通过嵌入能力测试后可建基本向量索引。P1 才评测关系限跳、社区及读路径融合 |

1. 按已提交变更顺序取一批对象。在数据库长写事务之外分词。保留原词频，另产生连续中文二元词与技术标识符拆词。正文位置保留来源字段路径或区间，词法扩展不覆盖原文。查某一时点的事实仍由 D2 选择对应修订。
2. 同批用稳定的「索引版本、来源版本、片段」键执行替换或移除。派生文件具有自己的就绪水位。先将该批索引变更持久化，再推进已处理的连续水位。两步之间中断时用原键重放。批中某条失败则保留未完成水位和失败对象，重启从该点继续。
3. 重建时旁建一份带版本的投影，追补构建期间的变更，验对撤回反例及一个仍可读的对照后切换活动引用。失败时保持原可用路径。语义检索另以授权域、模型版本、维数、切块和距离为键建新空间。按块读 float32 并算精确余弦 top-k。缺索引或预算不足时 M11 切回词法。向量关闭后不再向嵌入端点发送输入。[首版向量算法](../runtime-route.md)

**独立测试。** 临时数据根内经 D2 写入一条“溪桥导入超时”、一条另一项目的同名工件，另存含下划线的标识符。建词法、重放同一批、在推进水位前中止再启动。三次用相同查询对照有序的授权片段 ID，检查无重复、已追到同一水位。撤回第一条后故意暂停重建，旧命中经 M11/M12 出站时必须被拦下。向量关闭时用请求计数器检查建索引、查询、常规诊断的嵌入请求数均为零。[分词与索引对照](../compression-and-performance.md)

## M11 检索、融合与补读

| 端口 | 输入 | 输出及读取归属 |
|---|---|---|
| `POST /v2/search` | 调用身份、已登记的接收路由、用途、查询、任务或工件线索、`valid_at`、`known_at`、预算 | 在当前可见范围内返回稳定次序的修订、出处、证据是否充分和可展开句柄。排序信息供本地诊断，客户端不依赖原始分数 |
| `POST /v2/evidence/expand` | 原句柄、接收路由、上下文窗口或预算 | 交 D2 逐片解引用，返回获准窗口、来源角色、位置、截断或缺失原因。不可用对象按公共契约返回 404 |
| `GET /v2/tasks/{task_id}/handoff` | 已确认任务 ID、尝试/工件版本、当前接收者 | 读取 D2 已裁决经历，列目标、计划、执行证据、最后验证的结果、未解事项。多个同仓任务锚点重叠时先展示可见的选择线索 |

**查询顺序。** 解析当前调用者与实际目的地取得可见域。明确声明或事实键直接查 D2 的双时态修订。工作经历按任务、项目、工件和时间约束向 M10 要候选，限制所取数量，用稳定片段 ID 打破同分。按找到的修订、来源和任务对齐邻近片段，再逐项按今天的权限和有效性从 D2 补读。某段无权显示时一并剔除标题、预览、计数及跨段摘要。给不出答案时返回已有证据和缺口，有效查询无命中返回空集合。索引滞后或语义超时时报告降级。P1 比较融合、关系扩展和变长窗口时复用相同预算与最终检查。[研究回放及错例](../../../../research/reassessment-2026-11/local-evidence.md)

**独立测试。** 采用共享夹具的 `plan`、`run` 和 `control`，分别关联 `import-fixture@3` 和 `import-fixture@4`。[接力夹具](../interfaces/handoff-fixture.json)

第一场仅有计划，随后才收到同场同工件“解析通过、入库超时”的回执。按工件检索时先报未验证、收到后只标解析通过。按模糊任务名时保留候选。固定当前授权切换知晓时点验证迟到记录。固定历史时点再撤去读原文许可，使用旧句柄应得 404，同时独立授权的对照仍可展开。上述检查可独立使用真实 SQLite 和受控来源完成，不依赖在线生成模型。

## M12 全局声明装入、任务证据包装与回执

对上游接受 D1 已登记的宿主、会话、`context_epoch`、任务/尝试、路由、宿主已装入的 `known_snapshot_id` 和声明/证据两项 token 预算。对下游通过 `POST /v2/context/load` 返回 `snapshot_id`、`package_id`、`delivery_id`。D4 保存每组引用、实际提供修订、模板/策略版本、实际目的地与授权版本。M13 按投递清单验证宿主的后续回执。清单引用的说明和材料仍按当前授权读回。[请求响应样例](../contracts.md)

1. 先从 D2 直读已经生效且适用于本次任务的声明，按维度处理项目或单次例外。按接收范围共享的偏好字段独立于原会话的正文读取权限。声明不经过 M10 排名。确认同一 epoch 已装入相同快照才返回 `unchanged`。首次、重连未能证实装入、上下文重建或集合变化时返完整替换。集合清空时也要替换。声明预算不足返回 `deferred`、缺口和所需预算。
2. 用另一项预算读取 M11 的候选与证据。数据模式提供选定工作集完整表示，平衡模式合并重复字段和正文，高压缩仅对已通过相应模型/任务质量验证的模板使用紧凑表达，保留角色、否定、条件、修订和原文句柄。宿主不能主动展开时先补足必要证据，必要时回到已验证档。记录请求档、有效档、各次提供与展开用量。证据预算为零时返回 `budget_zero`，仍可投递声明。[压缩与质量约束](../compression-and-performance.md)
3. 在实际提供前根据当下路由和授权核对整包并记录此尝试的提供清单。响应提供成功才在外部报告 `provided`。中断而无法确认提供的尝试保留未知，重试按当前授权、epoch 和原请求重新判断。宿主的 `loaded` 与 `used` 由 M13 的独立观察确定。只支持追加文本的宿主若无法移除已撤权片段，应先重建干净上下文并记录原会话限制。

**独立测试。** 写入两维偏好后只改一个维度，关闭生成模型、暂停索引，用两条合成路由加载新会话。断言两者均取得获准的新修订，次要维度保留，受限路由看不到原会话。对同一会话依次执行缺回执、部分装入、完整装入、压缩新 epoch、授权收窄和预算为零，逐次核对替换/保留/推迟、所供 ID 和出站正文。用相同任务比较三档的候选顺序、关键事实和获准原文逐字回查。M13 的真实 Claude Code 与 Codex 回执及产物断言另作两宿主首发联调。[端到端场景 A01、A03、A04、A08](../../product/acceptance.md) · [反馈模块](feedback.md)
