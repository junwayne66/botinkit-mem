# D6 · 运营与治理

本域把所有者通过 CLI 或 Web 作出的设置与治理决定交给对应的写入方，持有可查询的单据、清理进度、备份清单与运行/发布记录。两端的同一业务修改使用同一应用命令，在任一端可回读同一修订、受理编号或失败原因。[操作契约与错误语义](../contracts.md) · [安装与配置所有权](../cli-and-platform.md)

## M16 来源设置、隐私和审计

| 用户意图 | 唯一的数据所有者 | 控制面收到什么 |
|---|---|---|
| 修改压缩档、连接器连接参数、模型和用途绑定 | 本机配置服务负责 `config.toml` 及配置修订，操作系统的凭据后端负责密钥。CLI/Web 共用 `GET/PATCH /v2/config` | 保存新版本后用任一端刷新都得到同一值。错误旧版本返回 `409 revision_changed`，凭据只显示可用状态 |
| 停/续采某来源、变更用途或接收者 | D1 管理连接、游标和可证明的覆盖点。D2 持有范围授权与撤回水位。M16 发送相应的 `stop_capture`、`resume_capture` 或 `change_grant` 应用命令 | 显示停止收新事件或已恢复的覆盖范围。用途收窄后下一次读取立刻按新版本。网络错误显示连接缺口。模型绑定不会赋予任何来源新的外发权 |
| 请求遗忘、撤回来源或训练用途 | D2 在一份短事务中生成操作 ID、更新禁读/用途水位、登记无正文墓碑及必要待办。D1 的可信上游撤回也走此端口。M16 维护逐位置清理单，D5 负责标识受影响的学习清单和工件 | 返回 `operation_id`、`effective`、`cleanup_state` 和下一步。受管副本、历史投递与系统外不可核验位置分别显示 |

对需要预览的操作，`POST /v2/operations/preview` 根据当前权限估算受影响的对象、字段、派生与历史投递，给出绑定目标修订、范围和授权版本的 `preview_id`。确认时任一端随同一意图、预览和幂等键调用 `POST /v2/operations`。事务中若范围已变，返回 409 重新预览。相同命令重试复用原单。M16 追踪执行器逐位置回报的结果，与 D2 共享首个受理事务，避免出现“显示成功、仍可新读”。待清理项按单据、位置及对象版本去重，重试仅领取未完成部分。查询清理和历史时仍按当前授权显示字段。[预览、撤回与逐位置读模型](../../product/governance.md)

**独立测试。** 对同一配置版本从 CLI 改压缩档，在 Web 用旧版本保存另一值，应见冲突，刷新后两端都显示 CLI 的新修订。交换两个入口再做一次。用两个来源分别控制只准本机读和明确准许共享的字段。停采前者后旧证据仍可按旧权补读。再在一端预览遗忘、另一端确认，暂停清理，此时旧句柄与旧索引命中均无法新读，而后一来源保留。恢复清理并故意令一个受管文件移除失败，两端都应查到相同单号、未完成位置和修复结果。

## M17 健康、积压、回放与发布

| 分期 | 读入与写出 | 执行约束 |
|---|---|---|
| P0 运行与队列 | 从 D1 读取源端覆盖点，从 D2 读取事务待办，从 D3 取得提炼运行结果，从 D4 取得投影水位。用 `GET /v2/health`、`GET /v2/jobs/{job_id}` 输出能力、已提交/已处理水位、最老待办年龄、失败类别和下一次可重试时间 | 调度设施只维护待办的领取、下一可运行时间和运行诊断，在有界线程中调用模块处理器。涉及业务裁决的完成标记与 D2 结果同事务提交。日志和诊断保留 ID 与耗时，省略用户正文、提示词和凭据 |
| P0 恢复或重算读索引 | 从受理单取得 `rebuild_index`、目标投影与输入水位，调用 M10 旁建，在健康页报告版本、水位和读路径 | 只重放仍可保管的输入。按原输入版本追补时比较今天的授权，旧来源已撤回则跳过。模型超时退避。进程中断后已过期领取可再次执行 |
| P1/P2 对照与发布 | 接收 M14 的配对评测和适用范围。P1 可以做只读影子检索比较。P2 登记训练工件、冻结报告、试用范围、目标指针与运行端实际加载版本，通过 `GET /v2/releases` 回读发布记录 | 先校验用途、工件和评测条件，再限域切换。实际加载确认才能计作已启用。回滚恢复合格指针，保留版本谱系与试用结果。程序升级版本单独由平台更新流程管理 |

启动时恢复过期领取，检查权威库、对象目录、词法和阻塞项。常规诊断读已有探测与队列记录。配置向导或显式模型测试可用合成输入验证用户正在配置的用途。向量关闭时常规启动与诊断跳过嵌入端点，显示“已关闭”。生成端点不可用要分别报告收件、声明直读、词法、提炼积压和实际失败。例如工作线程正常轮询且模型持续返回错误，提炼能力仍为降级。重试先找原待办，展示这次处理是否产生新修订、零项候选或已撤回。D6 的调度状态不能替代 D1 的接收回执、D2 的事实修订或 M13 的实际装入证明。[运行与重试](../operations.md)

**独立测试。** 固定两条待提炼来源，关掉生成端点，保留一条合法声明并撤掉其中一条待办输入。查询健康和作业，检验积压水位与最后失败原因。恢复端点并让真实处理器继续，查看一条可补读的新裁决和一条因撤回终止的任务。重启一次后无重复提交。在 P2 的独立实验中令运行端未加载候选或加载失败，发布页应区分目标版本、已加载版本和未成功范围。若前一版也依赖已撤训练输入，回到经核验的干净规则，最近的个人声明继续生效。[阶段验收](../../product/acceptance.md)

## M18 可移植导出、备份与恢复

| 操作 | 输入、产物与所有权 |
|---|---|
| `export` | 范围、用途与当前授权版本 → 可移植领域包。清单含格式、稳定 ID、来源/修订、双时态、依据边、授予范围、墓碑、游标、允许移交的附件及校验值，记录可证明截止点。移交后在单据标为系统外副本 |
| `backup` | 同一库世代的一致快照及附件清单 → 受管备份和独立的撤回清单。登记备份 ID、格式/世代、`change_seq`、撤回水位、对象哈希、位置及完整性，凭据和宿主绑定令牌排除在外 |
| `restore_preview`、`restore_apply` | 已登记备份、适用世代的独立撤回清单与现库预期水位 → 隔离核验报告、恢复可证明截止点、阻塞或待重授权项。应用引用核验成功的预览与原现库水位 |

1. 备份时使用 SQLite 一致快照，按快照引用固定原文和附件块至归档完成。校验摘要后才将备份列为完整。缺件或中断时保留可重试状态。领域导出逐对象应用导出权限。若备份/导出运行中获悉新的撤回，出库交付前复核，转入受管清理或重制受影响包。
2. 在隔离数据根还原库与允许的对象，核对格式、库世代、附件长度/哈希以及撤回清单覆盖是否连续。原机以现库最新撤回为下界。新环境以独立留存的可信撤回水位为凭据。独立清单与备份世代不符、缺段或只剩删除前孤本时报告可证明截止点，保持普通读写关闭。隔离期间不启动来源采集、模型或宿主投递。
3. 在隔离库重放已知撤回、重建索引，通过授权读取分别查询已撤回和保留的对照，核对来源、当前值、历史和允许的证据。将需要重新绑定的身份列入预览。切换前暂停新写、核对现库与预览水位相同再启用目标。若不同则重新预览。中断后根据记录保留最后已确认的活动库和预览状态，继续前核对水位。P2 还要校验学习清单、工件和部署的撤回依赖。[备份与隔离恢复口径](../operations.md)

**独立测试。** 在临时目录 A 写入共享夹具的两条独立工具来源 `run` 与 `control`，生成备份 B，随后撤回第一条并保留连续清单 C。分别在原库隔离区和空目录中用 B+C 预览、应用，检验搜索、原文、历史与新任务包没有第一条，第二条仍可读。再仅用 B、改坏一块附件、留一段清单缺口，各自应报告具体阻塞。预览通过后在现库追加声明，再应用旧预览应得 409。分别通过 CLI 和 Web 发起一次，另一入口按同一单据能查到库世代、截止点和处理位置。P0 合格需记录真实文件、数据库与查询结果，旧研究运行可作为用例来源。[接力夹具](../interfaces/handoff-fixture.json) · [研究恢复回放](../../../../research/reassessment-2026-11/local-evidence.md)
