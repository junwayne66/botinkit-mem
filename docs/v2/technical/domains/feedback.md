# D5 · 反馈与学习

D5 的在线输入是 D4 已提供的修订明细、D1 能观测到的实际模型输入和可定位的任务产物。它拥有观察、结果、数据集清单、评测与候选工件。纠正本人偏好走 D2 的声明写端，工具产生的新事实先走 D1 证据入口。运行策略由 D6 启用。P0 的用户可以获得完整的反馈与纠错链路，无需授予训练用途。[F11、F12 反馈与发布](../../product/feedback.md)

## M13 投递和使用反馈

| 输入端口 | 存储粒度 | 向宿主和管理端提供的结果 |
|---|---|---|
| D4 提供清单 | `delivery_id` 关联一次尝试、会话、epoch、路由、快照、任务包及已提供的修订 | M13 按 ID 引用 D4 的原清单。查看候选、提供、装入或采用时逐条关联，保留未知项 |
| `POST /v2/deliveries/{delivery_id}/receipts` | 观察键为已绑定的客户端与其稳定 `event_id`。记录观察类型、实际 `revision_ids`、模型调用或可定位行动引用，以及观察时刻 | `loaded` 要求宿主看到本次模型输入。仅装入部分时保留明细和原因。标记 `used` 需要修订与输出位置或动作的依据 |
| `POST /v2/attempts/{attempt_id}/outcomes` | 尝试、结果事件、独立验证器、工件版本、证据与关联投递。记录 `passed/failed/unknown`，另记尝试取消 | 同一次尝试的结果和逐条采用可分别查询。失败、超时、无回执及取消按各自状态汇总。重新执行建立新尝试 |

收到回执，先绑定调用身份与原投递的客户端、路由、epoch、版本，再比对所报修订是否出现在实际提供清单。一个短事务追加观察及去重回执。同键同内容重发复用原结果。异文同键或跨 epoch 绑定冲突走公共 409。与实际工件关联的晚到结果只更新对应尝试的读模型。独立结果无法证明某一次引用的贡献时，归因保持未知。声明改口时传 `corrects_attempt_id` 或 `corrects_revision_id` 回到 D2，由 D2 判定新值与作用域。读取既往观察时按当前授权裁剪明细。[投递和回执字段](../contracts.md) · [D4 提供清单](retrieval.md)

**独立测试。** 先用共享夹具的 `after_provided_only` 核对装入、采用与结果均为未知，再制作一次候选四条、提供两条、宿主仅实际装入一条的投递。先不给回执，再提交一条部分装入观察两次，随后给验证器一次通过回执。读 `GET /v2/deliveries` 应得到 4、2、1 三个阶段各自的明细，一次尝试通过，零条已有采用依据。增加可定位到输出首段的使用记录后仅该条为已采用。把同一回执改成另一 epoch 应拒绝计入。两款真实宿主分别检验其所能观察的阶段，将不可观测部分列为未知。[接力夹具](../interfaces/handoff-fixture.json) · [P0 双宿主验收](../../product/acceptance.md)

## M14 数据集与评测

| 分期 | 输入与工程产物 | 提供给谁 |
|---|---|---|
| P0 | 固定合成夹具版本、原始声明/事件、任务起点、独立结果断言和运行设置。记录两款真实宿主版本、路由能力、授权范围、提炼端点版本及各层可观测证据 | D1–D4 可按同一案例重放。发布记录按平台、宿主、模型、压缩档列出实际通过、失败或缺证 |
| P1 | 在事先登记的任务族上固定提炼器、阅读模型、token/时间预算，分别比较词法、补读、可选向量及增强策略。在提炼器对照中固定权威裁决器 | 给 M10/M11 或 M07/M08 返回错误位置、配对增益/退化及资源报告。用于调参的批次标明用途 |
| P2 | `build_dataset` 接收目的、计算环境、截止点和来源/任务族范围。保存不可变清单摘要、样本目标、根版本/任务族、观察依据、用途/环境许可、时间划分、排除原因与构建版本。评测侧另存冻结集 | 给 M15 训练和验证分区，给评测执行器独立冻结分区。通过 `GET /v2/evaluations` 查询有权限的报告。给 D6 输入适用范围、风险及放行证据 |

**构建与执行。** 按调用用途通过 D2 读取样本。用共享根或任务族做连通分组，改写、摘要及重试留在同组。按时间留出，跨越划分边界的簇整体划入一个集合或显式排除，查询仅带当时可知材料，金标和后来实际结果隔离给评分器。先提交清单，再按稳定的「清单摘要、策略、模型、预算、种子、任务、重复序号」记录逐次结果。中断后补缺失记录。中断与超时保留在分母。评测器用相同任务、可见信息与资源预算配对比较。报告任务通过/全部分配、最终输入证据充分/有合法充分证据任务、错误作答、未观测、授权正反例及每成功任务总用量。真实 token 含首次、补读和重试，缺少宿主计量时只发布已知估算。[评测方法](../../../../research/reassessment-2026-11/evaluation.md) · [三档准入判据](../compression-and-performance.md)

**独立测试。** P0 固定“准备复验、解析通过、入库仍超时”，分别以计划、真实回执和不相关任务做输入。断言错误的“整次成功”不会通过，下钻能区分候选漏检、交付缺证、宿主未观察、回答误用。P2 用五个样本组成原例、同根改写、同任务重试、仅在线许可项及独立留出。前三例同区，在线项被排除，留出样本只进评测区。撤销学习用途后旧清单停止取样和发布，重新构建后报告新摘要与分母。训练执行器的输入中不得出现冻结标签。

## M15 策略试验与离线训练

P2 才实现。输入是 M14 的已授权训练/验证清单、目标任务、基线规则、父工件版本、计算环境与资源预算。输出是候选清单，至少含工件摘要、配置/种子、所用快照、父工件、限定用途与受众、运行结果以及关联的独立评测。每个工件保留到训练运行和数据快照的反向路径，供 D6 查受影响部署。[策略与训练边界](../../../../research/reassessment-2026-11/feedback-learning.md)

1. 比较确定性策略与候选。先界定要优化的可测目标，例如筛出补读窗口或排序。策略试验可直接交付规则工件。执行 `train_candidate` 时复核训练用途和计算环境，训练执行器只领取已批准清单的允许分区，个人当前事实仍由 D2 提供。
2. 训练输出先暂存，形成可校验工件及运行清单后标记候选完成。按同一操作和输入引用重试时复用已完成工件。训练中断可以重新执行未完成的尝试，部分产物不能进入发布。训练或测试过程中输入授权变化时停用相关运行，并记录原因。
3. M14 用独立冻结集评测，D6 再决定影子、限定真实试用和发布。影子仅比较候选与开销。训练用途撤回时根据样本→运行→工件→后继工件定位受影响范围，交 D6 停用与回退。若已提交事实需要纠正，另发可追溯修订给 D2。

**独立测试。** 用获准合成任务运行小型确定性排序器，固定一个简单规则基线和两代继承候选。取消首轮训练，验证半成品未进入候选清单。重试后得到可核对的摘要、父子关系和冻结报告。撤回同时影响两代的训练来源，验证两代均无法发布，仍可选择无此来源的规则基线，回退后 M12 能读取刚追加的最新个人声明。测试归档能沿修订、样本、运行、部署各层找出受影响项。[A10、A11](../../product/acceptance.md) · [D6 发布与恢复](operations.md)
