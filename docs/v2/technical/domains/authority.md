# D2 · 证据与权威写入

D2 管理来源证据、事实和经历修订、依据关系、授权与撤回水位。CLI、Web 和受信宿主通过应用层进入同一短写事务。D1 提供身份与待推进的游标，D3 提供候选，D4 和 D6 读取已提交结果。能复用的表定义、区间语义及完整请求示例见[权威数据模型](../authority.md)和[服务契约](../contracts.md)。

| 模块 | 写入所有权 | 暴露给其他模块的行为 |
|---|---|---|
| M04 证据保管 | 根、不可变来源版本、证据片段、受控对象及其引用 | 接收有界事件页；按当前读取许可展开稳定句柄；向 D3 提供有权交给所选模型的片段 |
| M05 本人声明、经历与断言仲裁 | 声明与维度、任务/尝试、经历步骤、事实键、双时态修订、逐项裁决 | 同步追加本人原话、提交一批提案，按业务时刻/知晓时刻读当时判断 |
| M06 关联、授权与失效 | 修订与来源边、依赖组、授权版本、撤回水位、墓碑 | 判定具体读者/用途/目的地的可见字段，在撤回时阻断读取并登记清理范围 |

## M04 证据保管

**接收事务。** D1 以类型化的一页来源事件进入应用服务。M04 准备可留存的规范正文，再把本页交给一个 SQLite 写事务。下表是 D1、D2 与后台执行器共享的提交边界。[原文与无损编码](../compression-and-performance.md)

| 顺序 | 主责及写入 | 中断后可观察结果 |
|---|---|---|
| 1 · 准备 | 小正文随同事务内联。大对象在受控暂存区流式写入，固定原文范围、长度及摘要；完成校验、持久化后发布到同一文件系统上的受控位置 | 暂存失败时无受理回执，页游标沿用旧值。发布后、库提交前中断留下的无引用对象，在确认无在途写入及备份引用后可回收 |
| 2 · 开事务 | 先查同请求是否已有回执；复用时按现权裁剪。新页再核对来源、采集许可、当前游标、根的撤回水位及对象版本。按（来源、原生对象）和（根、原生版本）建唯一约束 | 旧源页不会复活被撤回版本；因快照过期未接受的页仍可从已提交游标重新拉取 |
| 3 · 写入并回执 | 写根、来源版本、角色、原生顺序依据、证据片段位置及对象引用；有撤回事件时同步调用 M06。追加变更和必要提炼/投影待办，同事务完成 D1 去重映射及游标推进 | 成功提交后才回各项事件结果、相关待办 ID 及已提交游标。响应丢失时同请求取得原事件/待办；失败回滚全部库内改动 |

**证据定位。** 根标识原生对象，事件标识特定版本，片段标识该版的字段路径或明确起止区间。结构化工具结果可定位到 `/checks/parse`、`/checks/write`。文本位置基于已获准留存的那一版原文，字符起止统一按 Unicode 标量值计数、从零开始、左闭右开。浏览器按此单位换算选区，存储层可额外保存 UTF-8 字节偏移和帧表。重新压缩仅改变物理位置。展开时由 M06 判现权并派生允许显示的窗口，撤回或无可见对象返回 `404 not_available`。被允许独立保留的共享声明字段按它自己的许可读出。

**独立验收。** 一页含短中文原话与跨压缩帧的长回执，分别指向计划、解析结果和入库错误。用临时 SQLite 库、真实受控目录和三种编码装载同一页；按原句柄逐段补读并比较字节、字段、来源版本。模拟附件已发布但事务未提交，以及已提交但未收到响应两种情况，核对其各自的游标、对象引用与待办数。

## M05 本人声明、经历与断言仲裁

`append_statement(original, scope)` 接受已绑定本人身份或受信原消息引用。返回 `statement_id`、逐维度 `status`、已形成的 `revision_id`、被取代的版及 `change_seq`。普通对话的候选通过 `commit_proposal(proposal, evidence_versions)` 提交，来源资格随原件保留。模型离线时确定性声明仍在本事务完成。

1. **找到比较对象。** 用命名空间内主体、可比较的谓词、规范适用条件与单/多值基数确定事实键。单值的取值变化属于同一键，多值关系比较相应客体。首次确定性声明使用内置有限词典；新词沿有依据的别名找原键，不能定键的原句记录为 `pending`。立即返回已经确定的其他维度；疑似冲突的同维旧默认暂停确定性投递。
2. **判断资格和时序。** 用户个人偏好由本人原话优先确定；工件执行结果须绑定真实运行、工件版本及相应字段。将意图、执行、结果和助手解释分开。遇同键冲突，比证据资格、条件及明确生效/事实发生时间，迟到资料可补历史。缺乏可分辨次序的等资格互斥值记 `disputed`。未来生效为 `scheduled`。项目例外只覆盖其范围内同一维度；单次请求仅适用其尝试或任务约定。
3. **提交双时态区间。** 在一个写事务内读取该键当前修订、当前知晓切片中的有效区间及候选依据。对接受的变更封闭旧知晓区间，在新知晓切片保留未变的有效时间段、切分被替代区间。开放上界表示继续有效。校验同一知晓切片的已决单值区间不重叠，写新修订与必要的依据/取代边、裁决和待办；原先知晓的历史继续可查。以主体/键/条件及时间建立查询索引。
4. **处理提案批次。** 相同 `proposal_id` 复用既有裁决。提交时检查输入版本、现行授权、预期事实修订，依序判断例如多条候选更新同一维度的结果。期间插入了新的本人纠正时，以新状态重新比较。把本批全部逐项裁决及作业完成状态放入同一提交边界；可判定的不成立候选有理由，事务级失败则整批重试。一个已成功的工具步骤不会赋予整次尝试成功状态。[提案样例](../authority.md)

**独立验收。** 停止生成端点，先从 CLI 声明“所有助手的报告用中文，先列行动项”，再从 Web 追加“以后报告先写结论”。两个入口回读同一 `r_lang1` 和新的开头修订；重试后一项不增加版数。再提交 11 月 8 日迟到的记录，证明某服务于 11 月 5 日改配置。查询 11 月 6 日的事实，以 6 日或 8 日之后为知晓截止应得到不同且可追溯的答案。另加未来声明、同名主体、计划与失败的工具回执各一条，分别检查当前视图与经历。

## M06 关联、授权与失效

| 操作 | 输入与读取顺序 | 提交/交付 |
|---|---|---|
| 绑定依据 | 每项事实或派生物提供准确到版本的边；同组必要前提全部满足，独立可证明的组各自登记。为被引用版本建反向索引 | 事实更正由新修订向旧修订登记 `supersedes`；来源佐证、反驳、依赖分别保存。基于同一根的转录不重复计数 |
| 读原文、现行声明或派生 | 先解析调用身份、用途与实际目的地，按**当前**授权决定可见字段，再选择事实时间与知晓时间，检查根/修订状态及必要输入。目的地不确定时按登记的可能目的地取共同可见集 | 只交付获准字段与稳定位置。独立获准共享的声明值和其原会话权限分别裁决。标题、摘要、计数、缓存与旧句柄遵循相同授权。D4 搜到候选后由此端口出站 |
| 修改授权、遗忘或源端撤回 | 本人治理命令带预览版本与预期水位。经认证的源端撤回由 `POST /v2/events` 直接进入。短事务写入新授权或墓碑、禁读水位、`change_seq`、受理单与清理待办 | 提交即覆盖在线读取。失效材料支撑的旧聚合先停供；有独立依据仍可成立时，由 D3 用剩余获准来源形成新版本。D6 按位置追踪清理、外部已发和无法核验范围 |
| 旧版回填与明确恢复 | 用对象身份、可证明的源端版本顺序及撤回水位检查。普通旧版去重返回被屏蔽状态。由源端撤回的对象只处理新的明确恢复事件及有效许可；本人已遗忘的旧对象仍受相应墓碑约束 | 异步索引重建、备份恢复和迟到提案均不能自行恢复普通可读性。操作完成与各处物理清理分别显示 |

**独立验收。** 用 A、B 两个原文共同支撑旧摘要，另设可独立支持某结论的 C。一个接收端只获准读取共享声明字段。暂停后台作业，撤回 A，立刻经原句柄、历史查询、旧摘要和再次装包检查禁读。获准的 C 与无关对照仍能读，恢复作业后由 C 成立的新版本明确列自己的依据。对一次过时的授权预览，从另一入口先收窄范围，旧预览提交得到 `409 revision_changed`。

三个模块的权威行为和故障恢复属于 P0。P1 的跨案例方法和图投影继续通过这些端口登记版本与依赖，D2 可先以合成输入独立验收，再接 D1 实际来源和 D3 实际模型。[阶段验收](../../product/acceptance.md)
