# D3 · 提炼与巩固

D3 把普通对话、工具回执与已有经历转成能回到原文的候选。D2 持久接受来源时产生待办，即使生成端点暂时离线也能继续收件。D3 输出提案给 M05，每个候选的裁决、经历修订与未成立的原因都能从作业追踪。P0 的联调顺序是先完成两宿主声明链路，再以真实模型处理普通消息和实际工具结果。[候选输入输出样本](../authority.md) · [模型与运行时](../runtime-route.md)

| 模块 | 自己维护 | 向其他模块交付 |
|---|---|---|
| M07 提取与模型路由 | 提炼作业、输入版本、实际端点/模型/模板版本、尝试次数、失败类别与处理进度 | 含位置、来源角色、工件/任务条件的结构化候选或有记录的零条结果 |
| M08 按事实维度归并 | 候选与拟匹配的事实键、预期修订、匹配依据和待补证原因 | 一批拟新增、合并、相抵或待判的提案；接收 M05 返回的逐项裁决与修订 |
| M09 经历归纳、方法与重算 | 归纳/重算作业、引用的经历版本、待补证与失效范围 | 针对具体任务的经历提案；P1 另交有多案例依据、适用条件和反例的方法提案 |

## M07 提取与模型路由

`extract(evidence_window, policy_version)` 的输入由 M04/M06 返回。窗口包含本次已获准发往实际端点的任务与尝试、工件版本和来源片段。每个片段有事件版本、说话者、消息种类、字段路径或原文起止位置。作业分别记录提炼策略版本与 M06 当次授权版本，前者用于复算候选，后者决定当时允许发送什么。执行器只从受控证据窗口构造请求。模型不能指定自己的身份、授权、`root_id`、事实修订或最终裁决。

| 步骤 | 输入 → 动作 → 持久结果 |
|---|---|
| 领取 | 从已到期的持久待办取 `job_id`，记录领取期限、目标、输入版本和策略版本。唯一键含作业种类、目标与输入/策略版本。相同输入报送多次仍可定位同一作业。配置未完成时显示待配并保留待办 |
| 组包与调用 | 按 `extract` 绑定选择端点，控制预算，保留每段的原件定位。临近发送时以实际端点、模型及登记的路由版本复核许可；同名模型修改 URL 或改指其他接收端后暂停发送，直到该目的地获准。生成 API 或 Ollama 调用在数据库事务外执行，P0 起始并发数为一。向量关闭时这条路径不需要嵌入模型 |
| 解析 | 检查提供方的完整结束状态、结构、字段类型、数量/范围约束和每项支持引用。结构损坏、输出被截断、引用未知片段时登记失败及阶段，保留完整输入版本供重试；合法的空数组以零条结果完成。对结构合法但证据不支持结论的单项，交 M05 留裁决理由 |
| 提交 | 为成功解析的批次关联 `job_id`、生成模型/模板版本、片段版本、提案及预期事实修订。输入重发和逻辑重试应重用已落盘候选，候选阶段存储受来源授权及清理规则约束。调用 M05，在同一短事务内提交逐项裁决/修订与本作业完成状态。即使重复领取也只能看见一次正式裁决 |

模型响应到达但候选尚未落盘的中断可再次产生模型调用，计量应保留两次尝试。超时或暂时端点故障按等待时间重试；配置/凭据不可用则停候并显示修复入口。重试重新取得证据与当前用途许可，来源已撤回则终止旧输入；输入版本已被替换时按新版本另行处理。已发送后再撤权的调用登记既有出站边界，在途结果不再凭旧权限生效。诊断最低字段为阶段、时间、用途、模型标识、原因、下次可运行时间，不回显提示词和原文。[后台执行与重试](../operations.md)

**独立验收。** 为真实调用适配层提供合成证据 `sp_u`（准备复验）、`sp_parse`（解析通过）、`sp_write`（入库超时），另给仅允许留在本机的哨兵片段。隔离协议端点检查实际出站内容和接收角色，分别返回合法结果、空数组、半截 JSON、未知片段 ID 和超时。核对每种结果是否调用 M05、是否产生确定性完成或可重试记录。再用选定的真实获准模型测提炼质量、输入/输出 token 与耗时，协议夹具仅用于故障和格式断言。

## M08 按事实维度归并

1. 按原句拆出能独立改变的维度。向 M05 的只读接口查询所属主体、谓词、条件、当前修订及已有证据别名。P0 使用共同的事实键与作用域规范化规则，以精确键和有证据的别名先匹配；相似文字只提供候选。明确声明的同步识别走 M05，复杂未决部分可用同一提案格式补充。
2. 对每个匹配给出 `kind, subject, key, value, condition, support, expected_revision`，并附发生/生效线索、极性及匹配原因。没有充分依据合并时保留两个备选或待判。未知主体、别名无依据和工件版本不符可分别追踪。归并只使用来源/用途允许的事实候选。
3. 交 M05 比较同一维度、证据资格与时态。一个批次内先处理的候选若已改写后续候选的目标，后者改按本事务中的现值比较。当前状态已有更正时返回对新修订的裁决，来源已不能用于此用途时终止。重放已处理提案返回原裁决，供作业和管理台按提案编号查阅。[仲裁与双时态](authority.md)

| 合成输入 | 归并输出 | 独立检查 |
|---|---|---|
| 已有“报告用中文，先列行动项”，本人后说“以后报告先写结论” | 拟匹配 `report.opening`，引用开头所在原句与预期版；不生成语言替换 | 经真实 M05 提交后保留语言原版，只有开头取得新修订。再送一次同批，修订数不变 |
| 助手转述某次工具结果，两个项目均有同名“导入器” | 转述带原证据根引用。仅按已证实的项目、工件与尝试匹配对应主体；定位不足时留待判 | 不增加独立工具运行数，另一个项目的当前事实不变。合成端点即使给高置信度也不能提升来源资格 |
| 生成提案期间收到新的本人更正，或收到同作用域可证明更早的证据 | 原提案附当时预期修订，提交时由当前 M05 判断新冲突或仅历史价值 | 核查当前值、历史知晓切片及逐项理由；迟到或弱来源不能凭入库先后覆盖新值 |

P1 可换维度匹配器，在相同候选、授权和模型预算下与 P0 配对比较错主体、错归并和漏归并，再交同一个 M05 产生可比裁决。

## M09 经历归纳、方法与重算

`consolidate(task_history, source_versions)` 读取同一已确认任务/尝试中允许用于本次归纳的输入。P0 根据原生角色、执行关联和工件版本整理意图、动作、可验证的结果、未解决项及各自的原文位置。权威经历由 M05 保存；D4 用这些经历组装接手材料，D5 的任务成败另由独立结果回执判定。

| 情况 | 算法与结果 | 独立验收 |
|---|---|---|
| 相同任务的计划与回执（P0） | 保留 `task_id`、`attempt_id`、`artifact_ref`；把用户的“准备复验”记为意图。把工具结果两字段分别作为“解析通过”和“入库超时”，附同一个工具根、各自的片段 ID。没有运行证据时仅保留计划或未知 | 给三片段加同仓无关任务。以真实 SQLite 权威库和 D4 读取端口查询，恰有对应计划和两个可验证结果，未解事项指向入库；接手不会混入别的任务，原回执的转述不另算验证 |
| 编辑、撤回和重算（P0） | M06 提交失效后，旧摘要在读取端立即停供；D3 按受影响的依赖反查作业，仅取仍获准的剩余依据。新摘要成版后交 M05 建立新的输入边；依据不足时保留缺口。重复撤回/重试沿用同一目标与输入版本 | 暂停 worker，撤回工具结果，原查看入口应立即拿不到两项验证。恢复 worker 后意图仍可见。有另一独立执行回执时，检查重算版的全部支持位置均属于剩余获准证据 |
| 跨案例方法（P1） | 按问题、可比工件/环境与结果分组；按独立根、尝试和案例去重。候选写明适用条件、支持案例、反例及失效范围，新工件版本的失败触发重新评估 | 先输入工件 v1 的一次成功及其转述，再输入 v2 的一次失败。只保留一次 v1 成功和 v2 反例；须能逐项回到实际回执。未满足条件的任务不得收到普适成功结论 |

**与双宿主合流。** Claude Code 实际执行测试工件，真实提炼模型输出候选，Codex 在新会话接手“溪桥导入”。按 `event_ref → job_id → proposal_id → revision_id → delivery_id` 对照实际裁决、装入/采用证据与独立工件结果。用正常权限完成一次，再收窄原文权限重试旧句柄。有一环无法观察时注明断点与仍可验证的部分。[首发自动提炼验收](../../product/acceptance.md)
