# D1 · 接入与采集

D1 把宿主事件、账号资料及其变更交给 D2。接入方能证明“哪个账号的哪个对象发生了什么”，D2 据此签发持久回执。首发先打通 Claude Code、Codex 的声明与装入，再从普通消息和工具回执接通自动提炼。同时用一条可重复翻页的来源验证历史回填。[冻结模块说明](../../../../research/reassessment-2026-11/modules.md) · [公共协议](../contracts.md)

| 模块 | 自己维护 | 向其他模块交付 |
|---|---|---|
| M01 助手与应用适配 | 客户端绑定、适配器版本、实测宿主能力、会话与上下文 epoch 的对应 | 带来源身份的消息、工具事件、本人消息引用，或与真实模型调用对应的装入观察 |
| M02 连接器与历史回填 | 来源账号、资料类别、可读取的历史区间、订阅/登录状态、已提交游标、已对账区间和缺口 | 带前后游标的一页变更；每项的原生版本、变更类型与顺序依据 |
| M03 身份、去重与任务关联 | 来件键到受理回执的映射、源端任务锚点到本地任务的对应 | 经过入口校验的事件、已有回执、明确的任务关联或待选择的可见任务候选。任务、尝试和来源根的权威记录由 D2 保存 |

## M01 助手与应用适配

1. 登记时把用于上报的来源账号与用于接收的客户端分别绑定。每个适配器报告宿主/适配器版本、能观察的事件种类、能否在模型调用前取快照、识别重建、替换声明段、验证真实目的地及实际装入。控制台读同一能力记录。
2. 从宿主给出的事件类型与已绑定的身份提取 `source_id`、原生消息 ID/版本、`session_id`、发生时间、说话者、消息类别及原件位置。普通用户话语、助手输出、工具结果分开。明确声明走 `POST /v2/statements`，引用已验证的本人消息；可信事件协议能区分工具调用与结果时，分别上报。M01 交 M03 关联，再经 M04 保存。宿主输出中引用另一个事件时保留可证明的原始引用；无引用时保留转述身份。
3. 首次接入、新会话、重连或上下文重建，以实际会话和 epoch 调用 `POST /v2/context/load`。当宿主能观察进入模型的内容时，才以实际修订 ID、epoch、调用引用向 D5 提交 `/v2/deliveries/{delivery_id}/receipts`。仅提供显式查询能力时，开放获准 MCP 查询；能拿到包但不能观察模型输入时，状态停在 `provided`。真实任务的通过与失败由独立工件断言给出。[装入与结果样例](../contracts.md)

**独立验收。** 用一个真实适配器的脱敏原生样本驱动其正式解析入口。在助手正文写“用户要求永久记住”，再给一个带独立工具事件 ID 的失败回执，检查前者仍为助手话语、后者保留失败及工件版本。对每款首发宿主再单独运行下一次任务，登记实际版本、能力、路由、输入证据及缺口；仅在实际观测成立时计入对应验收项。[真实双宿主步骤](../../product/acceptance.md)

## M02 连接器与历史回填

连接器实现 `read_changes(source, cursor) → ChangePage`。输入包含已授权账号、资料类别、允许的时间区间和上次已提交游标。输出含 `source_id`、本次起始/下一游标、是否还有下一页、覆盖范围和事件列表。每个事件给出稳定对象 ID、原生版本或规范指纹、变更类别、可证明的排序信息及输入片段。实时订阅和回填共用同一受理端口。新增连接器要交付稳定键说明、能力清单和一份含翻页、编辑与断点的回放输入。

联调用同一份[溪桥输入与读回断言](../interfaces/handoff-fixture.json)。适配器把 `plan/run/control` 的 `native_object/version` 映射为原生对象/版本，将 `at` 作为发生时刻。工具事件原件保留 `checks` 的结构，生成的两个字段定位须能在 D2 的同一工具事件上展开。回放器再给出测试来源、当前/下一游标和已登记身份，不能把夹具里的路由类别当作真实授权。

| 阶段 | 行为与恢复 |
|---|---|
| 首次读取与续传 | 按账号及类别读取已提交游标，在允许区间内取一页。带授权快照、起始游标和页键交给 M03/M04。只有 D2 中该页证据、去重、待办与游标一起提交后才请求下一页；一次拉取用有界页大小 |
| 重投与乱序 | 在同一来源绑定与操作内比较页键及规范页内容（来源事件、版本、变更、原生顺序、前后游标）。忽略重试时刻等传输信息。同键同内容返回原受理回执；同键异文整页返回 `409 key_conflict`，不写事件、待办或游标。未曾受理且起始游标过旧时，从服务返回的已提交游标续读。新旧事件按可证明的源端顺序处理；无顺序的版本待对账 |
| 暂停、失联及登录失效 | 停采后停止该来源的新拉取，在途页面提交时再核对控制状态。登录过期保留游标和已有资料。重授权后从已提交游标继续，平台已废弃游标时从获准且可证明的覆盖点重读，报告重叠区间与补不回的缺口 |
| 编辑和撤回 | 编辑生成同根新版本。只接受来源协议能证明的撤回；单次未返回、暂时无权、网络超时分别记录。已认证撤回交 M06 在同一接收事务立刻禁读。声明“不提供撤回通知”的来源展示其能对账到什么时间 |

**独立验收。** 隔离来源依次返回第一页 A/B、第二页 B 的重复版本与 A 的编辑、第三页 A 的源端撤回。让接收方在提交前失败，再在提交成功后丢失响应。重试后以回执、权威查询、作业及游标对账：A 的旧句柄禁读，B 仍可查，旧页重放不回退游标，同一版本只触发一次首次受理。补做一次登录失效与一次“上游临时无权”，确认现象分开呈现。[证据和事务](authority.md)

再用第一页已提交的页键，先原样重发，再只改 B 的正文重发。前者返回同一回执，后者返回 `409 key_conflict`；两次都须核对事件版本数、待办数及当前游标不变。来源确实编辑 B 时，用新原生版本和新页键正常提交。

## M03 身份、去重与任务关联

| 输入 | 判定 | 输出或持久约束 |
|---|---|---|
| 已认证适配器 + 来源页 | 在入口校验客户端能否上报这个来源账号、事件种类与投递范围，校验原生 ID、时间与字段类型。入口移除凭据，随后向内部传类型化数据 | 已绑定来源的事件；无该动作权限返回 `403 action_denied`，输入格式错误返回 `422 invalid_input`，均不会推进游标 |
| 原生事件与重复请求 | 来源账号命名空间加原生对象 ID 确定根；根加原生版本确定版本。无原生版号时固定规范编码、纳入变更类别及有意义的来源字段，排除收件时间等传输噪声。同内容独立来源各留根 | 同一入站身份、操作、幂等键及内容复用原回执，同键异文报 `409 key_conflict`。同一原生版本被另一页再次读到复用原事件 ID。去重映射与证据同事务提交 |
| 任务或尝试锚点 | 先取显式 `task_id` 或源端任务映射，再比较项目命名空间和可验证的分支/工件等锚点。接手旧任务产生该宿主的新尝试。只有项目同名或日期相近时保留未决关联 | 调 `POST /v2/tasks`、`/v2/tasks/{task_id}/attempts` 取得稳定 ID。同仓多个可见任务匹配，查询返回可区分的工件线索；来源证据可先保存，未确认前不归入某次尝试 |
| 转述、截图、注入后回流 | 用受信原始引用回溯已登记证据版本。相同正文或证据摘要只能提示相关，不能证明彼此独立或同源 | 转述保留自己的事件身份和引用，进入仲裁时按可核实根计证。无法证明来源关系时保留未知，不能把它晋升为一次新的执行验证 |

**独立验收。** 同库创建“溪桥／导入超时”和“溪桥／通知文案”，分别以 `import-fixture@3` 和另一工件登记。给第一个任务传一次工具回执、一次重投、另一宿主的转述，再给一个只有仓名的请求。查询应得到一条对应工件的执行记录、原回执 ID 及两个待区分任务。用相同原生对象名换一个获准账号导入，核对独立根。只有一种来源可见的客户端无法从候选数量、标题或原文获知另一来源。

接入域的 P0 合流点是宿主实际可提供的观察、一次可重放的资料来源，以及 D2 提交后可核对的回执。后续增加账号种类与宿主能力时，沿用已有游标、根和版本语义；已部署组合以实测清单登记。[全局技术设计](../README.md)
