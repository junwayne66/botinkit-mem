# 命令登记、双入口写入与扩展

领域实现一次动作，命令行和网页调用同一个应用处理函数。比如 CLI 的 `bmem config set profile high` 和网页的「高压缩 → 保存」都提交 `config.patch`。此设计也适用于新增连接器、声明、授权、重试与恢复。每项可以执行的用户操作见[命令与网页对照](command-catalog.md)。

## 一个动作怎样登记

实现时由模块随代码声明能力，组装 `bmem` 时合并为一份注册表。CLI 用表核对 clap 解析后的绑定，本机 Web 用表取得动作、输入约束和可用状态。特有的交互界面可手写，保存和结果回读必须走该绑定。服务启动时拒绝重复的「ID、契约主版本」组合、矛盾的路由分派、缺失的处理函数、未注册的向导步骤及循环步骤。Schema 要求面向所有者的写动作或向导都登记 CLI 和 Web 入口；集成测试再通过两个真实入口执行并回读。

| 字段 | 开发约定 |
|---|---|
| `command_id`、`contract_version`、`stage` | 稳定的点分动作名、该动作的正整数契约主版本、最早交付期。安装版本只登记它能解释的能力。相同动作的不同交互写法可映射同一 ID |
| `kind`、`cli`、`web`、`http` | `query` 为读取，`action` 为一个服务动作，`workflow` 按 `steps` 编排已登记动作，`local` 用于启动/定位程序等必须在主机进行的动作。协议入口列 HTTP 方法与路径，共用治理路由时用 `selector` 标明 `kind`。工作流自身没有第二条 HTTP 写路径 |
| `input_schema`、`output_schema`、`authority` | 对应类型的输入输出 JSON Schema、可调用身份类别。服务在入口解析身份和有类型输入，结合实际来源、当前用途和目的地授权裁剪结果。发现能力不能作为授权凭据 |
| `concurrency`、`handler` | 标明只读、幂等、比较修订、预览确认、逐步提交或本机动作；指向唯一应用处理函数或工作流。处理函数名只随制品登记，对外能力目录隐藏此字段 |

[描述符 JSON Schema](interfaces/command-descriptor.schema.json) 和[P0 设置变更描述符](interfaces/config-patch.example.json)可直接用于契约测试。设置契约覆盖三档、向量开关、模型、用途绑定和连接器的本机参数。各配置所有者贡献有类型的键，合并后拒绝未登记的键。CLI 和 Web 可先用档位变更合流，再逐一接入模型、连接器和凭据选择。[设置请求和正反例](interfaces/config-patch.md) · [JSON Schema 2020-12](https://json-schema.org/draft/2020-12)

CI 将校验器随包提供的 Draft 2020-12 元 Schema（含各词汇表的标准 URI）注册到离线资源表，再按 `$id` 登记本地消息 Schema。所有 `$ref` 只从该表和当前文档解析，缺失资源直接报契约错误。设置写入还需用同一请求与成功回执检查条件字段、动作和对象 ID。[离线复验命令](interfaces/config-patch.md)

`bmem capabilities list` 对应 `GET /v2/capabilities`，返回 `items`、`next_cursor`。每项有 `command_id`、`supported_versions`、`kind`、`stage` 和 `available`，已登记但尚未就绪时另给 `reason`。`bmem capabilities show config.patch --json` 对应 `GET /v2/capabilities/config.patch`，返回所选版本的 `descriptor`（去掉内部 `handler`）及相同的就绪字段。工作流只列调用者有权获知的步骤。执行时仍按本次请求身份鉴权。

P0 公开契约版本 1。读取详情或执行动作可带 `Bmem-Command-Version: 1`；省略时使用该动作在 `/v2` 的基线版本。若请求版本不在 `supported_versions`，服务在进入处理函数前返回 `406 unsupported_contract_version`。增加可选字段且保留原语义时沿用主版本；删字段、改必填或改变副作用时登记新版本。调用方可先发现支持的版本再提交。

## 从任一入口修改，再从另一入口读回

| 顺序 | 以切到高压缩为例 |
|---|---|
| 读取 | CLI 编辑命令和 Web 表单先读取 `GET /v2/config`。假定当前 `config_revision=7`，同时读取到 `profile=balanced` |
| 提交 | 两端均向 `PATCH /v2/config` 发 `{"expected_revision":7,"patch":{"profile":"high"}}`，同一意图的网络重试沿用同一个 `Idempotency-Key`。服务只解析本次指定键，把变更后的快照交给配置所有者 |
| 生效 | 对同一数据根串行比较修订，写同目录暂存 TOML 后原子替换。该快照含新修订和本次请求的身份范围、键及规范输入摘要。响应示意 `{"config_revision":8,"profile":"high","vector_search":{"enabled":false}}`。后续组包采用新设置，历史对象重打包进度单独回报。设置及压缩编码的两个生效时刻分别可见 |
| 回读 | 成功后两端都按权威修订刷新。网页再次获得焦点时重取配置，运行中的长操作仅在详情页打开时低频按 ID 查询；CLI 下次读取直接访问同一服务。两个界面各自维护草稿，草稿从未对外生效 |
| 失败或结果丢失 | 不同意图提交过期修订返回 `409 revision_changed` 并给出当前修订，保留用户草稿供比较。同一已提交请求按幂等契约复用回执。服务重新启动时从文件读取提交修订。若文件写入失败，内存和对外读取仍指向上一完整修订 |

**配置回执与业务回执分别落盘。** 对数据库动作，把幂等键、输入摘要、对象/操作 ID 与业务效果写在同一 SQLite 事务中。对修改 TOML 的动作，将最小回执随配置快照一同替换。P0 建议保留最近 64 次成功的配置提交；帮助和契约明确这个重放范围。收到重试时先按主体与键查原回执，输入一致返回原提交修订，不一致返回 `key_conflict`；无匹配回执时才比较预期修订。即使已超出窗口，旧请求也因其过期修订返回冲突，不会覆盖新设置。回执只持有修订、结果定位和非敏感对照信息。凭据变更按受控凭据版本作比较，响应和回执均不存密钥原文。重放只交付当前仍有权读的字段，原操作结果修订与当前配置修订分别显示。

**跨存储分步提交。** 需要录入密钥时，两个客户端先调用仅所有者可用的 `credential.store`。服务把输入写入凭据库的新版本，回传引用，再让 `config.patch` 把配置快照指向它。第二步失败时旧绑定仍可用，续办可重用暂存引用，放弃后回收未采用引用。无桌面凭据库时可直接绑定服务环境变量名。连接器的本机端点、账号登记和采集授权分步确认，业务权限及游标只读 SQLite。保存端点后若授权未完成，两端都显示待授权；后台只领取已获准的来源。恢复向导按完成步骤的稳定结果接续。涉及撤回、遗忘、恢复切换等影响范围的修改使用同一预览、预期版本和操作单。[治理契约](contracts.md) · [安装与存储](cli-and-platform.md)

**主机动作。** 安装程序、在尚无服务时拉起进程和打开浏览器由本机引导器执行。服务在线时，网页里的持久平台设置及升级请求交给与 CLI 相同的本机执行器，由持久回执报告实际结果；服务重启后用原操作 ID 续查。机器上还没有程序或任何页面时，用户从安装制品开始。宿主的真实「已装入」或工具执行结果必须带对应身份和观察，管理台与所有者 CLI 可以查询这些记录。[宿主回执](contracts.md)

## 增加能力时改哪些边界

| 扩展对象 | 增加什么 | 必须通过的接入检查 |
|---|---|---|
| 用户命令或设置 | 在所属域增加类型、处理函数、描述符和两个入口的绑定。普通设置可使用通用键值表单；有影响范围的动作实现预览和确认。向导引用既有原子动作 | 实际 CLI、Web 都能修改、互读；错误、过期版本、重试结果一致。帮助、能力发现和契约示例能定位此动作 |
| 来源连接器 / 宿主 | 通过 D1 的来源事件与游标协议接入，登记原生版本、编辑/撤回覆盖和宿主实测能力。内建适配器随 Rust 制品登记工厂；独立进程可经已登记来源身份提交 `POST /v2/events`。宿主可用受权的 MCP/HTTP 工具读取 | 重投同页只接受一次，收到撤回后旧原文禁读，角色出自可信入口。缺某项能力时对外如实展示。独立进程无需取得数据库文件或所有者管理凭据 |
| 生成 / 嵌入模型 | 单独实现 `extract` 或 `embed` 适配，登记用途、协议、合成探针与模型版本。可通过已有协议接新端点；新协议由内建提供方适配 | 未开启向量时嵌入调用为零。模型离线时声明可用，提炼待办可重试。实际接收路由和用途授权与发出的材料可对照 |
| 检索投影 / 上下文表示 | D4 注册建索引、查询及水位读端，或增加按任务选择的序列化模板。候选均返回类型化引用；补读由权威层鉴权 | 相同授权/数据/预算回放，检查候选、最终证据和回查。撤回水位先于清理生效；三档的质量与成本分别测量 |
| 评测器 / 发布策略 | D5 登记输入用途、冻结集与评分器版本，D6 登记实际启用范围和回退目标。P1/P2 启用对应能力时才公开相应动作 | 能复算配对结果；用撤回样例追到数据集和所有后继工件，运行端确认切回合格版本 |

例如接入一个能分页读取开发日志的新来源，新增来源类型描述及实现，让 `bmem connector add <type>` 和网页连接器列表共同发现该类型；复用既有事件信封、授权预览与游标回执。先在隔离目录投一页日志，重投该页，再撤回一个对象，核对一条受理回执和双入口可读的处理结果。这条接法可以在 P0 实施。新增需要随程序加载的协议适配器时重新构建制品；第三方进程已有受限 HTTP/MCP 接入路径。热加载本地二进制插件、插件市场可在出现相应分发需求时另定协议。
