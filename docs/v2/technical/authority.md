# 权威数据与事务

所有可见值都能定位到一个修订、来源资格、适用条件及作出裁决的时间。下列名称是新库的逻辑表与索引设计；接口只暴露稳定 ID、版本和授权字段。来源原文、声明和合成示例应在入口先移除凭据，再产生任何持久内容、附件或日志。[冻结生命周期](../../../research/reassessment-2026-11/memory-lifecycle.md) · [知识图模型](../../../research/reassessment-2026-11/knowledge-graph.md)

## 数据布局

| 对象组 | 标识、关键字段 | 写入约束与用途 |
|---|---|---|
| 客户端 / 来源 | `client_id`、宿主能力、经绑定的目的地集合；`source_id`、所有者、来源账号、可采事件类型、游标、对账水位 | 采集、本人声明、补读、学习分权限。原生账号和对象名只在获准的详情中返回 |
| 根来源 / 来源版本 / 片段 | `root_id`、`source_id`、`native_object_id`；`event_id`、`native_version`、`actor_kind`、发生/收到时刻、变更类型、摘要；`span_id`、事件、字段路径或字符起止 | 根按（来源账号命名空间、原生对象）唯一，版本按（根、原生版本）唯一。无原生版本时适配器生成规范变更指纹并登记排序依据。提及、转述、注入回流关联到原根 |
| 声明 / 声明维度 | `statement_id`、本人来源、清理后的原话、声明作用域、生效线索、共享意图；每维度记录状态、裁决理由和可用修订 | 个人原话来自所有者入口或可验证宿主用户消息。语音/导入文档内的引述、模型自报用户身份不能取得直接声明资格 |
| 实体 / 事实键 | `entity_id`、项目/来源命名空间、类型、原生锚点；`fact_id`、主体、谓词、规范条件 | 同名实体分开保存。已证实的别名留依据。单值事实按主体、谓词和规范条件定位；多值关系分别识别客体。全局/项目/一次任务为不同范围 |
| 事实修订 / 时间段 | `revision_id`、事实键、值或客体、极性、前任、规则/生成版本、`valid_from/to`、`known_from/to`、裁决状态 | 双左闭右开区间；结束为空表示尚未封闭。已决单值键在同一知晓切片的同一适用条件内不能重叠。留存旧判断及理由，查询可重放 |
| 版本关系 / 依据组 | 新修订 → `supersedes` → 旧修订；结论修订 → `derived_from` / `supported_by` / `refuted_by` → 原文片段或上游修订。每组记录组号与所需输入版本 | 同一组的前提全部成立，多个可独立证明的组可择一。以被引用版本建反向索引。取代边、共现、相似度不增加独立根数 |
| 任务 / 尝试 / 经历 | `task_id`、项目、分支/工件锚点；`attempt_id`、宿主、会话、开始/结束；步骤的意图、执行动作、观察结果和证据 | 重试为独立尝试。以明确任务锚点关联；同仓同日命中两个任务时返回二选线索。只有计划时，结果为未知 |
| 授权 / 撤回登记 | `grant_id`、版本、所有者、对象范围、允许的客户端/来源账号、用途、接收路径、字段；操作水位、`root_id` 或受影响对象封禁标识 | 删除保留仅供匹配旧键的无正文墓碑及水位。对象遗忘阻止同一旧对象重导。来源协议有可信版本顺序时，上游撤回水位屏蔽旧版本；任何后继恢复须有明确的源端恢复事件和有效授权 |
| 派生物 / 投递 / 观察 | 派生 ID、全部输入版本和投影水位；`snapshot_id`、`package_id`、`delivery_id`、所供修订、目的地、授权版本、宿主 epoch；独立观测带事件 ID、事实依据 | 物化标题、向量、摘要、包与缩略图一并登记依赖。投递清单默认存引用和版本，读取说明也过当前权限。装入、采用和任务成败各自入账 |
| 变更序号 / 待办 / 单据 | 每次权威提交单调递增的 `change_seq`；待办种类、目标与输入版本、领取/重试状态；`operation_id`、各位置处理结果 | 同一事务内产生全部必要待办。待办去重键含种类、目标、输入版本/策略版本；清理和恢复单据由执行结果更新 |

活动事实按（主体、谓词、条件、时间）建索引，关系按两个端点分别建索引；依赖反查以来源版本、派生版本建索引。权限和有效性在读取时刻统一判断，模型或管理界面都须走同一套应用命令。[端口](contracts.md)

## 四个提交边界

1. **接收一页来源。** 验证已注册来源账号、采集范围和输入格式，移除凭据；先将允许保留的大附件从暂存区原子持久化，再提交其引用。一个事务写入该页各事件版本、出处、去重回执、提炼待办和下一游标，已接受的重投只复用回执。页面中出现撤回时，在同一事务关闭旧版本及其依赖读取。页失败保留原游标；回收无引用附件时避开尚在写入或被快照引用的内容。
2. **提交声明。** 所有者声明跳过模型价值筛选。内置、有限的维度词典和有来源的别名可确定主体、键、覆盖关系及取值时，短事务一起写原话、各维度修订、依据、裁决、版本变更和待办。投递可用值在提交后立即可查。复杂句未决部分先返回 `pending` 和具体原句，疑似互斥的旧值暂停作为该范围的确定默认值；后续提炼/新证据自动重算。用户始终通过追加表达改口。
3. **提交后台提案。** worker 读取输入版本、可用证据范围、提取/规则版本及预期事实修订，释放事务后运行模型。提交时比较输入可读性、授权版本和事实当前修订。相同提案重放复用原裁决；事实已变时基于当前状态重新比较，来源已被撤回时终止该提案。权威事务写入接受、合并、仅历史、待归并或争议的结果及理由。
4. **改变授权或遗忘。** 首个事务生成操作单、推进授权/撤回水位、关闭相应读路径、产生清理待办。读取某个派生物须验证全部必要输入当前可用；索引、依赖队列或磁盘清理尚未完成时同样执行。多个独立依据组之一失效时，旧摘要先停供，可由剩余证据产生一条新的可读版本。所有者更正普通偏好只追加事实历史。

## P0 普通对话与工具回执的自动提炼

在 Claude Code 与 Codex 的声明链路通过后，给同一对真实宿主接上来源事件和提炼 worker。本人平常说的话以 `user_message` 采集，助手猜测或计划用 `assistant_message`，工具真实输出用 `tool_result`；正文角色词不能改变来源资格。普通消息无需说“记住”。每个输入片段带来源版本和可复查位置。一次提炼可以涵盖同一任务的几个获准片段。

**模型输入。** 下列是隔离联调可制作的合成片段。适配器掌握真实身份与原件，worker 按提炼用途与模型接收路径筛选字段后才组装输入。模型在库事务外调用，输入水位、模型/模板版本和任务锚点写入本地作业记录。

```json
{
  "task_id": "t_creek_import", "attempt_id": "try_21", "artifact_ref": "import-fixture@3",
  "inputs": [
    {"event_ref":"msg_21@1","kind":"user_message","span_id":"sp_u","field":"/text","value":"这次我先单跑解析，再查入库超时。"},
    {"event_ref":"run_21@1","kind":"tool_result","span_id":"sp_parse","field":"/checks/parse","value":"passed"},
    {"event_ref":"run_21@1","kind":"tool_result","span_id":"sp_write","field":"/checks/write","value":"timeout"}
  ]
}
```

**模型输出。** 模型为每项建议语义、条件与位置，稳定的根来源、修订和裁决由服务填写。一个工具回执中的两项检查共用一个根。缺少足够信息时可返回空数组并记录已处理。

```json
{
  "candidates": [
    {"kind":"plan","subject":"t_creek_import","key":"next_step","value":"先单跑解析","support":["sp_u"]},
    {"kind":"execution_result","subject":"t_creek_import","key":"parse","value":"passed","condition":"import-fixture@3","support":["sp_parse"]},
    {"kind":"execution_result","subject":"t_creek_import","key":"write","value":"timeout","condition":"import-fixture@3","support":["sp_write"]}
  ]
}
```

| 权威提交检查 | 自动结果 |
|---|---|
| 输出符合候选格式，主体和工件匹配；`sp_u` 仍定位本人原话，`sp_parse`、`sp_write` 对应本次运行的两个字段 | 计划作为本次尝试的意图，后两项按已验证回执分别写入带条件的经历修订，原文和证据边随修订可查。接手卡可显示“解析通过，入库仍超时” |
| 另一条普通用户消息“溪桥开发环境一直用样例库”，没有声明触发词，尚无配置或执行回执 | 提炼为带开发环境条件和原句位置的本人陈述，可在获准的溪桥任务中按来源找回；后续有独立配置或执行证据时再按该事实维度归并。不得自动扩为全项目全局默认 |
| 助手猜测、说话者复述、无法定位的支持，或模型把整次任务判为通过 | 猜测保留其来源和不确定状态，重复根不增信；缺有效定位或结果与回执不符的候选不进入已确认结果。不能从一次运行推断长期偏好或跨案例通法 |
| 同一作业重试、运行期间来源撤回或工件已有新版本 | 以输入和策略版本去重；提交前重查权限与输入版本，旧来源撤回则停止该提案。新工件按新版本另立或重算修订，保留原版本的事实时间 |
| 端点超时、断开或返回结构无效 | 当次不写事实，待办带失败类别/重试时间；恢复后重新核对授权及源版本，按原任务补提炼，或记录因撤回而终止。测模型恢复须观察新的权威裁决和宿主读到的修订 |

观察采用同一链路关联 `event_ref → job_id → model_version/template_version → proposal_id → revision_id → delivery_id`。受权所有者从任务卡可回查原片段；接收宿主只取得该路由允许的证据。P1 在此基础上对照跨案例方法归纳、反例覆盖及提炼器改进。

## 同一句话如何改变两个宿主

以下以合成授权路由展示字段裁剪，真实 Claude Code 与 Codex 路由分别核验。设所有者先声明“所有助手的报告用中文，先列行动项”，稍后追加“以后报告先写结论”。声明原文只准云杉本机读取，白桦仅获准在指定云模型装入共享偏好字段。

| 时点 | 写入 / 读取结果 |
|---|---|
| S1 提交 | 生成 `st_1` 及两个维度：`report.language=zh` 修订 `r_lang1`、`report.opening=actions` 修订 `r_open1`，共同指向本人原消息。共享声明字段另有所有者授权 |
| S2 提交 | `report.opening=conclusion` 产生 `r_open2`，指向被取代的 `r_open1`；语言仍为 `r_lang1`。停机的 worker、长期未使用及索引重建都不改变结果 |
| S2 后甲乙装入 | 各按自身的接收路径读取 `r_lang1`、`r_open2`。云杉有权查来源时另得原文句柄；白桦只收共享字段，连无权的原会话标题和同会话邻句也不发送 |
| 用户更正“这条以后仅用于溪桥” | 可明确指认原全局维度且原话表达收窄时，在同一事务结束该全局修订的适用期、建立溪桥范围的新修订并关联被更正版本。溪桥以外的下一份快照撤下该维度；其他维度保留。若指向不清走待归并 |
| 特定项目另有例外 | 已确认的项目例外覆盖同维度全局默认；其他项目沿用全局值。并列互斥且无法裁决时返回 `disputed`，标记该维度缺少确定值 |

## 时间和授权的查询顺序

例如配置在 11 月 5 日转为分批，发布记录于 11 月 8 日才抵达。原判断“11 月 1 日起串行”的知晓区间在 8 日封闭；新知晓切片登记“1 日至 5 日前串行”“5 日起分批”。查 6 日的业务状态时，知晓截止取 6 日得到串行，取 8 日提交后得到分批。查某次实跑方式要读该次运行证据。

1. 由已验证客户端、所有者、来源账号、实际接收者/可能路由和用途取得**今天**的授权。请求传入的业务日期或知晓日期仅用于选事实。查询返回条数、建议词、图标题和邻近片段均受同一可见域限制。
2. 选满足 `valid_from ≤ valid_at < valid_to` 且 `known_from ≤ known_at < known_to` 的修订（开放上界视为无穷）。依当前任务条件确定范围。范围越具体只在该范围覆盖；后来到达的旧证据可补早期区间；收件时间相近不能裁定事实先后。未来生效值在边界时刻由查询表达式选中，宿主下次装入能发现快照变化。
3. 按字段资格读取。独立共享的声明投影仅需其自身当前共享授权和仍可使用的声明依据；原会话正文要具备读原文权限。普通组合摘要要求每项必要输入具有当前读与派生资格。循证据边、限跳关系和组装最后出站包时同样检查；服务端将记忆编码为带来源的参考材料。
4. 若接收路径未能验证，用客户端登记的所有可能目的地的共同可读字段；连目的地集合都未知时只供应明确允许任意相应目的地的数据，其余返回路由受限。已提供内容如已进入系统外上下文，单据记录其投递范围。下次出站读取按新授权重算。

## 可重放的不变量

| 输入 | 必须看到的结果 |
|---|---|
| 同一页重投，另一个助手复述同一原句 | 一个根版本、一次受理；可查独立支持根数仍为 1 |
| 计划“准备复验”随后收到“解析通过，入库仍超时”的工具回执 | 接手卡分别列计划、已验证范围和未解事项，每项能回到自己的来源 |
| 在后台计算时有一次本人纠正或权限收窄 | 提案按当前事实重新裁决或停止；旧任务结果既不能覆盖新值，也不能送到无权接收端 |
| 两个同名组件、一个后来补录的旧值、一个未来声明 | 实体分开、历史能解释先后；未来值在生效边界后才显示为当前 |
| 撤回一个联合前提，并保留无关来源作对照 | 受影响的旧摘要、标题或原文句柄当即不可读；独立且仍授权的对照继续可查 |
