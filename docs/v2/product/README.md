# Botinkit Memory 产品功能设计

一位所有者在多款助手之间继续工作。所有者向其中一个助手声明偏好，另一个助手接手时取得适用的版本和原始依据。用户可以查出谁收到过什么，也可以更正某个条件、收窄用途或要求遗忘。首个演示从一条有两个维度的声明走到第二个宿主的实际输出。[架构总纲](../../../research/reassessment-2026-11/architecture.md) · [演示脚本与验收口径](acceptance.md)

## 功能范围与入口

| 功能 | 交付阶段 | 用户如何完成或检查 | 交互入口 |
|---|---|---|---|
| [F01 来源接入与用途授权](governance.md#f01) | P0 | 选择来源账号、资料范围、接收者和用途，查看回填覆盖与缺口 | U4 来源与用途 |
| [F02 声明与按维度纠正](memory.md#f02) | P0 | 在对话、CLI 或管理台追加本人原话，查看逐项生效结果 | U1 当前声明 |
| [F03 宿主装入与回执](memory.md#f03) | P0 | 新会话直接提出任务，核对各宿主所用的声明版本 | U2 装入回执 |
| [F04 任务接手与原文补读](memory.md#f04) | P0 | 找到指定任务的最后一次验证、遗留问题和原文 | U3 任务接手 |
| [F05 历史与出处](memory.md#f05) | P0 | 从当前结论追溯旧修订、当时依据和后来获知的更正 | U1、U3 详情 |
| [F06 撤回、遗忘与清理](governance.md#f06) | P0 | 核对立即生效的读取限制、清理进度和已发副本 | U5 撤回与恢复 |
| [F07 备份与隔离恢复](governance.md#f07) | P0 | 预览备份水位、缺件与撤回覆盖，再决定是否切换 | U5 撤回与恢复 |
| [F08 运行与降级](governance.md#f08) | P0 | 在相关来源或宿主条目找到失败原因、可用能力与重试结果 | U2、U4、U5 内联状态 |
| [F09 自动提炼与方法归纳](memory.md#f09) | P0 基础提炼，P1 跨案例归纳 | 从普通对话及工具回执自动提取有出处的事实与经历，供另一宿主接手 | U1、U3 详情 |
| [F10 关系、语义与主题阅读](memory.md#f10) | P1 | 从授权范围内的问题进入多跳出处、跨项目主题或证据缺口 | U3 证据区 |
| [F11 反馈与归因](feedback.md#f11) | P0 观察与纠正，P2 取样 | 对照装入的版本、实际采用和独立结果，纠正错用范围 | U2、U3、U6 评测与发布 |
| [F12 学习、评测与发布回滚](feedback.md#f12) | P2 | 查看候选相对基线的得失，在获准范围启用或回到合格版本 | U6 评测与发布 |

P0 分两步。先让 Claude Code 与 Codex 跑通声明、装入和回执，再用这两款真实宿主产生普通对话与工具回执，接入真实提炼模型。首发时，用于接手的事实或经历须能从授权原文经候选、自动仲裁，追溯到另一宿主实际采用的修订。后台模型停机时仍可采集、声明、治理与词法补读，恢复后处理积压。P1 比较提炼器质量和替换收益、跨案例方法归纳、有限跳关系、语义补读和主题汇总。P2 以具有独立来源和学习授权的样本改进规则或模型。[交互设计](../ui/README.md) · [技术方案](../technical/README.md)

## 身份和用途

| 参与方 | 能发起的动作 | 用户可检查的边界 |
|---|---|---|
| 记忆所有者 | 追加声明、设置范围、核对证据和结果、授权用途、遗忘或恢复 | 新声明显示原话及裁决，控制动作返回受理结果和影响范围 |
| 已注册宿主及其实际接收端 | 提交经核实的本人消息或工具事件，按授权查询，按实际能力报告装入、采用或结果 | 每次交付绑定宿主、会话及接收路由。仅提供查询工具的接入显示「仅可查询」 |
| 来源账号及连接器 | 按所选范围交付历史、新增、编辑和可感知的撤回 | 原系统作者、账号和对象版本随材料保留。外部资料中的偏好只具有该来源的证据资格 |
| 后台提炼、检索和学习组件 | 在获准环境处理相应材料，返回候选、引用或工件 | 候选经权威仲裁才成为有效事实。学习、远端处理和在线读取有各自的用途授权 |

**用户日常只需追加表达。** “这次只要一段”作用于当前任务。“以后项目甲只要一段”建立项目条件。“我说错了，这条只适用于乙”生成更正修订。“忘掉这段会议”进入范围可见的遗忘流程。以上动作分别产生可检查的当前值、历史或删除结果。自动归并后无需用户编辑旧正文或逐条审核。[声明与冲突规则](../../../research/reassessment-2026-11/memory-lifecycle.md)

## 交付检验

每项功能的正文给出情境、规则和可观察结果。首轮由 Claude Code 与 Codex 联调，经普通宿主入口、公开接口与管理台重放授权的合成工作任务。记录两款宿主的实际路由、版本、使用的修订及独立结果。所需环节缺观察时，登记该项验收待完成。文中用例均为待实现的设计判据。[验收脚本](acceptance.md) · [冻结调研的评测口径](../../../research/reassessment-2026-11/evaluation.md)
