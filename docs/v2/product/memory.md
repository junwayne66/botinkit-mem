# 声明、接手与证据阅读

<a id="f02"></a>

## F02　声明与按维度纠正 · P0

当我改变长期习惯时，我希望只说一遍，让下一次工作采用新值，同时保留其余习惯。对话中的本人消息、受信的本机 CLI 和管理台使用同一条声明流程。提交时可选全局、项目或任务条件，声明的适用范围与原文可以交给谁分别设置。

| 触发和操作 | 回执与下一次可观察结果 |
|---|---|
| 1. 本人说“所有助手的报告用中文，先列行动项” | 同一原话产生“报告语言”和“报告开头”两项，回执列出作用范围、当前修订和来源。两个维度各自可追溯 |
| 2. 追加“以后报告先写结论” | 提交成功即读到“中文＋先写结论”。开头的旧值转入历史，语言维度保留原修订。相同本人消息重投仍返回原回执 |
| 3. 用户说“这次用英语”，随后说“项目溪桥以后用英语” | 本次任务按临时指令输出，下次其他项目仍用中文。后一句只在溪桥取代语言默认值，开头继续先写结论 |
| 4. 声明标明下周一生效、或仅本周有效 | 按声明发生地明确的时区展示生效边界。生效前显示待生效，到期后的普通读取回到仍适用的默认值 |
| 5. 新原话含以上下文无法判定的维度，或两个同等资格来源取值相冲突 | 先交还收录回执。未判清的细目显示待归并或争议，普通任务能取得已确定的部分。在授权范围内可显示带不确定性标记的本人新原话。后续证据到达自动重判 |
| 6. 提交同一段助手转述、较早发生但延迟导入的声明，或一年未使用的有效偏好 | 转述保留作者身份，迟到资料可补历史。当前有效值只因证据与适用条件改变。一年静默后新任务仍取得同一项 |

声明行的状态为已生效（`active`）、待生效（`scheduled`）、待归并（`pending`）、有争议（`disputed`）和历史（`historical`）。一次声明可产生不同状态的几行。当前与历史的展示都要通过发起查询时的权限检查。[冻结的归并与取代规则](../../../research/reassessment-2026-11/memory-lifecycle.md)

## F03　宿主装入与回执 · P0

当我更换助手或恢复旧会话时，我希望直接交办任务，并知道当前偏好何时真正进入该次上下文。首次登记按能力标注宿主能否在回答前取快照、识别上下文重建、替换声明段、确认实际路由、上报装入及关联结果。

| 情境 | 宿主动作与验收 |
|---|---|
| 1. 新会话只收到“汇总今天的工作” | 答复前拉取当前范围的声明快照。检查宿主实际上下文中的语言、开头和修订，再核对输出。查询文本无需含偏好关键词 |
| 2. 同一会话继续，所有者只改了一项 | 下一次可控模型调用前核对版本并替换声明段。仅能追加的宿主提供明确取代标记，页面提示旧上下文可能仍含先前文字 |
| 3. 上下文压缩重建或离线宿主重连 | 新上下文重新装入当前快照，断开期间保留最后可核验装入与时间，重连后直接同步最新适用版本 |
| 4. 云杉走本机。白桦走云端且只获准共享偏好。另接一个仅可搜索的客户端 | 云杉在本机授权内可回源。白桦取得可共享声明，受限原句不进入云端输入。仅可搜索的客户端显示「仅可查询」 |
| 5. 路由无法确认、预算不足或仅取得服务响应 | 路由未知只提供所有可能目的地共同获准的信息。未能完整装入应显示受限或待装入，保留实际装入明细。服务已提供（`provided`）与可核实的已装入（`loaded`）分列 |
| 6. 宿主装入后输出用了旧值或没有回报最终结果 | 原装入记录可查。只有可定位的输出或动作才把对应项记为已采用（`used`）。任务结果独立记录通过、失败或未知，缺少结果回执时显示未知 |

声明通道单独保留预算。任务证据与声明在同一授权目的地下分别裁剪、分别计量。排队期间失效的内容在送出前剔除。已经交到宿主的版本保留送达记录。[装入状态的归因边界](feedback.md#f11)

## F04　任务接手与原文补读 · P0

当我把一个未完成任务交给另一助手时，我希望它从已经核实的步骤继续，并能点开当时的回执。接手卡展示目标、来源任务、适用版本、已执行步骤及结果、待办、最后验证状态和来源位置。

| 情境 | 取证和交付结果 |
|---|---|
| 1. 溪桥“导入超时”与同仓“通知文案”同时进行 | 先按任务标识、工件或分支定位。标识不足时提供获准的候选供选择，详情显示用于区分的线索，两条经历保持独立 |
| 2. 日志写有“准备复验”，工具稍后回报“解析通过，入库仍超时” | 接手卡的计划区显示准备复验，执行区显示解析通过、入库超时，遗留项为定位入库超时。每个结论指向相应工件版本及原句 |
| 3. 词法检索命中计划所在消息，完成状态位于相邻消息 | 展开句柄可以取得同一授权来源中的邻近证据。包标明采样或截断。只取得计划时，结果显示“尚无可核验回执” |
| 4. 授权收窄后再展开上一次交付的句柄 | 重新核对当前接收端和用途，受限句柄无法返回旧原文。卡片可用仍获准的独立依据重建，保留范围变化提示 |
| 5. 用户切到另一版本，或搜索得到一次失败的方法 | 返回历史版本、适用前提、失败或未验证状态。证据仅支持一次执行时，交付该次结果。应用于新版本仍须验证 |
| 6. 冻结任务没有历史、有近似但无关任务，或语义索引离线 | 对空结果显示“没有适用证据”并允许继续任务。授权原文存在时可用精确或词法路径补读。语义命中数单列，不参与判断任务是否完成 |

## F05　历史与出处 · P0

当我发现助手的回答和上周不同，我希望按照“什么时候有效”和“当时已经知道什么”解释两次答案。详情展示主体、范围、事实修订、有效区间、知晓区间、原系统作者、原文位置和取代原因。

| 验收操作 | 可观察结果 |
|---|---|
| 1. 查看已被新声明取代的报告开头 | 当前页显示“先写结论”，历史页列“先列行动项”的适用区间、两条声明的先后和各自出处 |
| 2. 在合成配置中，11 月 1 日知道“默认串行”，11 月 8 日获得“从 11 月 5 日起分批” | 同查 11 月 6 日的配置，以 6 日知晓水位回看为串行，以 8 日水位回看为分批。界面同时列出两种时间 |
| 3. 询问 11 月 6 日某次作业的实际运行方式 | 有该作业回执才给实际方式。仅有默认配置时说明缺少该次运行记录 |
| 4. 原始材料经两个助手转述 | 关联到同一根来源，在许可范围内可展开转述链。独立依据数为一 |
| 5. “桥接器”在两个项目中重名 | 按项目和来源对象身份分别列出。原句无法消歧时保留未决提及及获准的定位 |
| 6. 上周能读的来源今天取消访问 | 今天发起的历史查询沿用今天的权限。可共享的确定声明按其独立授权展示，来源正文、摘要或标题若受限一并隐藏 |

## F09　自动提炼与方法归纳 · P0 基础提炼，P1 跨案例归纳

当我正常工作而没有专门说“记住”时，我希望另一助手能接着已验证的步骤工作，也能识别失败和猜测。P0 的真实提炼器读取已获当前运行环境授权的普通对话与工具回执，产出有片段定位、角色、任务和工件版本的事实或经历候选。服务自动裁决，获准的接手宿主取得已接受修订并在下一次工作中使用。单次经历只表述其观察到的条件与结果。

| 输入或操作 | 应见结果 |
|---|---|
| 1. 一段日志依次出现猜测、试做、回执 | 候选逐项注明原句、主体、结果和版本，猜测与已完成动作各有标记。缺重要证据可产生零条有效候选 |
| 2. 来源转写、截图或摘要全来自同一条消息 | 视为一次根证据，多个转述不会增加方法成立的案例数 |
| 3. 仅在版本 1.0 观察到一次成功，2.0 又遇失败 | P0 分别保留两次经历和工件环境。P1 尝试跨案例归纳时，方法附支持它的独立案例与失效条件，并可逐项回源 |
| 4. 本人声明与外部资料中的偏好相反 | 外部叙述保留原角色和范围，个人默认按有效本人声明处理 |
| 5. 模型超时，或生成候选后来源已撤回 | 待办显示超时或失效。恢复运行时按现授权和来源版本处理。已撤回的原文和仅凭它生成的候选退出交付 |
| 6. 等资格证据彼此冲突，随后收到可判先后的独立回执 | 先展示不确定性，有足够依据时自动更新结论、条件和修订。普通用户无需维护审核队列 |

首发联调使用 Claude Code 中的普通工作对话和真实工具结果，让 Codex 在新会话中采用经仲裁的经历修订。每个候选及裁决保留处理版本、来源和是否生效的理由。额外放入未执行计划、失败结果、同源转述和未授权片段，逐项查到各自处理结果。P1 在此基线上比较提炼器替换带来的错主体、误归并、漏提和成本变化。[P0 验收脚本](acceptance.md)

## F10　关系、语义与主题阅读 · P1

当我换一种说法询问旧经历，或要找不同项目的共同变化时，我希望助手找到完整证据，也告诉我哪些部分仍无法证明。检索路径随问题类型选择，在固定任务预算下逐项比较。[知识图的合成示例](../../../research/reassessment-2026-11/knowledge-graph.md)

| 问题或变化 | 可接受交付 |
|---|---|
| 1. 当前偏好是什么 | 读取授权现行修订。关闭向量、图和社区后仍可得到相同现值 |
| 2. 改用近义词、中文双字词或技术标识符询问旧故障 | 返回具体版本、相关原文和邻近执行回执。命中会话但没有充分依据时标记证据缺口 |
| 3. “导出作业依赖的组件，6 日默认怎么跑” | 给出作业到组件、组件到模式的有向证据链和两个时点。缺一跳只交付已证明部分 |
| 4. “本月获准项目发生哪些共同变化”或“究竟多少个组件” | 主题列逐项原文。精确计数按可见实体去重，附范围和完成水位。社区名称、成员和频率限定在相同许可范围内 |
| 5. 撤去联合前提之一或发现两个同名组件合并有误 | 依赖该前提的旧路径、标题、摘要立即退出查询，重新计算获准证据。可独立推出的结论用其余完整证据重建 |
| 6. 新组件在某类题上没有可复现收益 | 回到该类题目的已有路径，保留相同的声明和原文读取入口。按逐任务、同预算结果决定启用范围 |
