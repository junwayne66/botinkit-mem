## F11　反馈与归因 · P0 观察与纠正，P2 形成样本

当助手收到几条记忆并完成任务时，我希望知道其中哪条实际用过、依据在哪里，从而能纠正错用的那一条。一次尝试绑定任务、宿主会话、本次上下文、实际送出版本、使用的策略和可定位的结果。相同回执重试只记一次，重新执行任务产生新的尝试。

| 观察 | 产品呈现及判定 |
|---|---|
| 1. 服务选出四条，只实际提供两条，宿主能证实装入一条 | 分别保存候选、已提供（`provided`）和已装入（`loaded`）的明细。列表显示未装入的原因或未知，不以服务端返回替宿主确认 |
| 2. 最终文档采用“先写结论”，验证器通过两条格式断言 | 对能定位到输出开头的声明可记已采用（`used`），任务尝试单独记通过（`passed`），并链接工件、版本及验证回执 |
| 3. 工具报告测试全部通过，但无法定位某条材料的贡献 | 尝试记通过，该材料的采用或增益记未知。点击、沉默、点赞、未展示仅作为观察 |
| 4. 任务失败（`failed`）、没有独立回执（`unknown`）或取消 | 显示各自原因，取消计入单独数量。失败归属本次尝试，不能把包中所有材料标负 |
| 5. 用户说“刚才用了别的项目做法，今后仅用于溪桥” | 若能定位本次错用，则关联该尝试和具体修订。新的范围要求走本人声明通道，即使没有训练授权或模型停机也生效 |
| 6. 输入可定位、有多次近似转述、或许可只覆盖在线 | 分别按任务、根来源和查询时点生成有明确目标的正负例。弱或不可归因信号进入观察集合。仅在线许可的记录不得进入离线样本或训练日志 |

P0 先对声明核查权威修订、实际装入和产物，再对自动提炼复用这条观测链。用 Claude Code 的普通对话与工具回执生成经历，检查 Codex 此次尝试采用的修订、它所依据的候选与原文，以及最终动作的独立验证。缺少采用证据时该层为“未知”。[端到端验收](acceptance.md) · [冻结调研的信号定义](../../../research/reassessment-2026-11/feedback-learning.md)

## F12　学习、评测与发布回滚 · P2

当系统提出启用新排序规则或提炼器时，我希望知道它在留出任务上改善了什么、代价是多少，以及停用后会影响哪些工作。进入本阶段的前提是用途许可覆盖样本构建、计算环境与发布范围，且有足够独立任务用于比较。无学习授权或样本不足时继续使用原规则。

| 谁在何时做什么 | 可检查产物与决定 |
|---|---|
| 1. 所有者首次启用离线学习 | 指定范围、本机或获准的处理环境、学习目的。个人适配器的受众受此许可约束。来源与所有者的限制须同时满足 |
| 2. 构建训练、验证与冻结评测清单 | 展示快照、成员、根来源、任务族、样本标签依据、构建版本、划分、许可及排除理由。同一原文、改写、摘要与同一任务重试归同簇，按时间留出，查询输入不能含后来的结果与修订 |
| 3. 评测候选 | 与当前线上版本、仅显式声明和基本规则使用相同查询、预算、任务起点与读取模型。报配对改善和退化、证据齐备率、关键切片、成本及不确定性。每次评审能追到候选和冻结集版本 |
| 4. 影子与小范围启用 | 先旁路比对输出差异和时延，评审页标“影子”。满足预登记条件后才对获准任务实际使用，按分配记录任务结果、缺失及所用版本。样本不足继续原策略 |
| 5. 候选出现越权、已撤回内容复活、遗漏必须装入声明或关键切片超限 | 停止投放并回到合格的策略或规则基线。权威事实按最新修订继续服务。若此前的提炼器曾写出错误断言，按证据追加纠正，给出受影响的修订清单 |
| 6. 撤销训练用途，要求移除既有影响 | 阻断新取样、训练和发布，列出快照→训练运行→工件与后继→部署的依赖。停用受影响工件，核实替代版本从未用过该来源，或用净化后数据重训再评测。受管副本清理与外部已导出状态分别报告 |

### 如何判断收益

| 问题 | 计算口径 | 谁用来决定什么 |
|---|---|---|
| 声明传到了多少个应接收的会话 | 确认装入当前完整快照的会话 / 本轮有主动装入能力且获准的应装入会话。离线、预算不足、仅查询与缺回执另列 | 所有者判断能否换助手直接工作 |
| 用户还需要反复纠正吗 | 遵循偏好的产出 / 有实际装入且可评价的产出，以及重复纠正次数 / 有相同适用偏好的任务数。列缺观测及一次要求误扩为长期的数目 | 对留出任务分别给零、少量、更多历史与仅声明，比较稳定偏好及项目例外 |
| 任务做得更好吗 | 真实通过任务数 / 全部分配任务数。同时报失败、超时和缺失，以及同任务从失败到通过、从通过到失败。按根任务簇给出配对区间 | 决定是否扩大当前候选的适用范围 |
| 是否找到完成任务所需的全部证据 | 最终输入覆盖所有必要依据数（按任务计） / 有授权充分依据的任务数。无答案题另报错误作答，完整证据链按任务逐项核对 | 对比原文词法、语义、补读或关系路径，定位应该改进的环节 |
| 能否继续相信用户控制与成本 | 受限信息披露 / 受限读取机会、合法任务误拒 / 允许机会、撤回后重新出现 / 撤回后机会。列每成功任务总用量、冷/热 p50/p95、后台训练/重建资源 | 任何已证实硬约束失败立即停用候选。仅对硬约束全部满足的版本比较任务收益与代价 |

运行前登记候选、基线、样本版本、目标切片、最小业务收益、可接受退化与资源上限。分母为零记“无观测”。小样本列出独立簇和具体成败。冻结集一经用于调参，后续收益声明改用新留出批次。撤权导致的样本变化以新清单和新分母重新评测。数值门槛须基于目标设备与预期任务负载预先确定。[发布与回滚判据](../../../research/reassessment-2026-11/feedback-learning.md)
