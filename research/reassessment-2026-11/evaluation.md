# BMEM 的记忆效果怎样验收

**调研截至 2026-11-19。** BMEM 有三个不同的验收对象。第一，系统能否取出此刻适用且该读者有权看到的证据。第二，另一个助手得到证据后，工作结果是否改善。第三，用户是否理解系统留下了什么，能否纠正、更改共享范围和撤回。公共对话问答主要覆盖第一个对象的一部分。建议把三者分别列入发布评审。

### 复核旧调研的三个关键口径

**公开题库的分母。** 从作者固定提交读取并解析 `locomo10.json`，得到 10 段会话和 1,986 道题。类别 1 至 5 各有 282、321、96、841、446 道。前四类共 1,540 道。作者代码对类别 5 单列拒答评分。HEAMS 明确排除了这一类。报分时同时写明会话数、类别、评分器和实际分母。一段对话衍生多道题，统计不确定性以会话为簇。原件 SHA-256 为 `79fa87e90f04081343b8c8debecb80a9a6842b76a7aa537dc9fdf651ea698ff4`。 [LoCoMo 固定数据文件](https://github.com/snap-research/locomo/blob/3eb6f2c585f5e1699204e3c3bdf7adc5c28cb376/data/locomo10.json) · [原版评分代码](https://github.com/snap-research/locomo/blob/3eb6f2c585f5e1699204e3c3bdf7adc5c28cb376/task_eval/evaluation.py) · [HEAMS 表 2](https://arxiv.org/html/2611.20144v1)

**同名基准的版本。** LongMemEval 作者在 2025-09 公布清洗版，移除了干扰答案正确性的会话。建议固定数据快照 `98d7416c24c778c2fee6e6f3006e7a073259d48f`，注明 S/M 或 oracle，以及是否允许裁判看到原文。LongMemEval-V2 是另一套工作环境经验题，451 题，small 级 100 条历史轨迹、medium 级约 500 条，作者用紧凑证据回答问题。MemoryArena 则让后续会话的行动依赖前一会话反馈。两者能分别定位“知道怎么做”和“后续实际做到”。 [LongMemEval 作者变更说明](https://github.com/xiaowu0162/LongMemEval/tree/9e0b455f4ef0e2ab8f2e582289761153549043fc) · [清洗版数据快照](https://huggingface.co/datasets/xiaowu0162/longmemeval-cleaned/tree/98d7416c24c778c2fee6e6f3006e7a073259d48f) · [LongMemEval-V2 v1，§3](https://arxiv.org/html/2605.12493v1) · [MemoryArena，ICML 2026](https://proceedings.mlr.press/v306/he26am.html)

**“忘记”和“可信”的判据。** Memora 在回答中处罚重用已过时的事实。ForgetEval 用 1,000 道模板题、385 道挑战题比较修改操作，用子串检测返回结果。二者均不能证明原始正文、旧快照、索引都已清除。AuthMem-Bench 保持断言内容固定，只变更来源角色，49 种模型与归纳器组合中有 48 种至少出现一次权威升级。这不是 48/49 条个人记忆错误。CPB 则固定复制谱系，区分多次转述与独立支持。BMEM 应同时测误晋升和真事实被误拒，后续读取、实际使用、回流为新来源是三个不同观察点。 [Memora，Findings ACL 2026](https://aclanthology.org/2026.findings-acl.1337/) · [ForgetEval v2，§3–5](https://arxiv.org/html/2606.15903v2) · [AuthMem-Bench v2，实验设计与结果](https://arxiv.org/html/2608.01679v2) · [CPB v1，图 1、静态与动态协议](https://arxiv.org/html/2609.30813v1)

## 建议的 BMEM 回放与判定协议

以下是待执行的产品协议。每个场景由同源事件族、按到达顺序的写入、更正/分享动作和多个时点的问题组成。先固定一次独立抽样与评分约定，再打开测试结果。金标包括事实的生效区间、允许读者、最小充分证据集合、允许与禁止的字段、预期工具结果。判定“今天已知什么”时，只开放该时点已到达的材料。另设“回看当时实际有效事实”的问题，允许利用后来核实的记录，二者分别标注。

| 试验与反事实 | 具体做法 | 输出与决策 |
|---|---|---|
| 中文工作记忆召回 | 在不同会话中改写同一事实，覆盖工单号、短汉字、英文标识符、中英混写和无词面重合的别名。另放同名项目/过时修订作为干扰。每套配置从同一空库重放。 | 报证据集合覆盖数/应给数、全部必要证据齐全的题数/有答案题数、逐题所引修订、无答案误答率。多跳题只找到其中一个节点时计部分召回，不能计充分证据。 |
| 写入与污染 | 配对同一断言的用户明确声明、工具回执、第三方转述、助手推测。加入同一根来源的三次回流与两次真正独立核实。 | 分别报抽取漏失、错误源角色、独立证据计数错误、误晋升/应不晋升、误拒/应晋升。保留后续助手使用过的修订与是否再次写回。 |
| 无人工参与的提炼和冲突淘汰 | 用正常宿主输入同一段含两项明确偏好的会话，让后台自行提取、定位到原文并生效。模拟经过一段长时间、期间无人提及，再输入一条与其中一项冲突的新声明，另重放发生较早的旧证据。 | 全程不操作管理台。两项原偏好在仅经过时间后均应有效。新声明只取代同一主体、同一适用条件下冲突的一项，另一项保持原修订。检验当前查询只采用新值，按当时状态回看仍能解释旧值，晚到旧资料不推翻新事实。 |
| 共享偏好的自动读取和后续纠错 | 用户对甲说“所有助手的报告用中文，先列行动项”。在每个已接入助手的新会话仅要求“汇总今天的工作”，再追加“项目乙今后先写结论”。最后以新消息声明“项目名说错了，刚才的变更只对丙有效”。覆盖新开会话、已有会话的下一次任务及后来接入的助手，保留一个无权读取原会话的读者作为对照。 | 分别统计收到当前声明的助手数/应收到的助手数、下一任务遵循数/已收到数。检查甲乙丙各项目的顺序和语言，确认只变更目标范围。通过宿主实际使用的输入检查送达，无需用户搜索或提到偏好关键词。受权共享的偏好可送达，受限的原会话正文须单独鉴权。 |
| 读权限与撤销 | 同一合成记录分别通过受权和未受权读者查询。撤销前后核对最终注入、搜索摘录、证据详情、图和摘要。通过本地捕获的测试接收端检查可出站字段，使用人工合成标记与人工语义复看。 | 记录拒绝动作及各表面具体出现的限制字段、允许字段命中和合理任务的错误拒绝。一个未授权读者出现限制数据即判该用例失败。全文字符串扫描只能覆盖可观察字面值。新读者 ACL 属方案待验能力。 |
| 删除与修正 | 从同一快照分出两种请求。“今天改用 B”仍应能按历史权限解释当年的 A。“清除 A 的内容”按留存合同分别查当前库、派生项、索引、恢复后的可读性。保留不相关条目验证误删。 | 分列覆盖面、残留字段/应清项目、被误删/应保留项目和最慢生效时间。没有访问某个备份或终端即记未核验。 |
| 跨助手任务效用 | 甲在玩具仓库记录成功做法或已证实的失败原因，乙在新会话完成另一任务。正例含版本/适用前提，负例含版本已变或毫无关联的任务。禁用目标测试答案、目标补丁及其衍生记录。 | 锁定代码起点与测试，记录每任务通过状态、错误操作、步骤数、用时和输入输出 token。若直接给金标无改善，优先检查题目是否真正依赖历史。若有金标改善而自动检索无改善，再看写入、排序与组装。 |
| 人的知情与纠错 | 给参与者合成工作记录，请其找到“为什么另一个助手知道此事”。让用户通过普通新消息说明“这项偏好只适用于项目甲”，观察系统生成新修订。另测撤回共享后哪些接收者可读。 | 报纠错成功、首次定位用时、实际读取者、状态预测正确率，并检查界面、工具和 API 均不提供直接覆写旧记忆正文的入口。用途适切度由参与者独立评价。 |

### 对照、预算和不确定性

1. **按根事件族划分训练/调参与冻结评测。** 原始会话、摘要、人工改写、同源证据不能分居两边。跨项目泛化另留整项目。时点切分须阻止未来版本、后补答案或测试改动进库。按任务簇而非题数分配样本。先报告每片有多少独立簇。
2. **配对比较。** 同一任务依次对照关闭记忆、固定窗口最近对话、原始片段词法、原始片段向量、融合、再单加修订/有证据关系/重排。另设同预算随机无关片段以检测上下文增量本身的影响。金标证据只用于诊断。完整上下文仅在模型可容纳时单列成本和上下文长度。读取模型、提示词、工具权限、最大步数、时间上限一致。写入次数、嵌入时间和内存另记。
3. **记录系统真正交给读者的内容。** 每个用例分别记录事件抵达、正确版本可见、是否实际交给该助手、回答和操作结果。共享偏好检查会话启动装载及变更送达。任务经验另查检索候选与最终预算。两类结果分别报分。当前 BMEM 的回注预算使用中英混排估算函数。跨模型对比另以实际 tokenizer 或响应 usage 复核。金标 `source_id` 命中应对回源，区分“支持该回答”与“相关但不充分”。 [回注实现](../../src/bmem/store.py) · [回注请求字段](../../src/bmem/models.py)
4. **报告效应大小与分母。** 给出同题从失败变成功、成功变失败的个数，以及成功率差的 95% 区间。共享同一会话、项目或场景的题按簇配对重采样。独立簇很少时公布逐簇结果并保留不确定判断。随机求解器在相同任务做多个重复，单次成功率与多次取最好结果分别报告。隐私违规的门槛可以是零观察，样本量必须随同呈现。例如即使 100 个独立同分布机会中观察到 0 次，一侧 95% 精确上限仍为约 2.95%［1−0.05^(1/100)］。同一会话的 100 个改写不满足独立假设。
5. **预先约定放行条件。** 确定性约束失败先处理。允许输出和限制输出都要通过。对可选检索器，以冻结的业务权重、资源上限、配对任务通过率和区间作决定。若测量无法区分两条路线，记录哪一类缺样本。若特定切片有收益且其他切片退化，可按可观测的请求类型单独评估启用。
