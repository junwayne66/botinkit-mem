# 长期记忆系统再调研

**结论：bmem 下一步最值得测的是，一条应该记住的原话有没有变成正确的当前事实，以及任务需要它时，助手到底拿到了哪段证据。** 本轮在 V2 的同一声明入口观察到，“全局报告用中文”立即生效，“今后所有代码示例使用 Rust”则停在 `pending`。当前声明解析覆盖报告语言与开头两个维度；如果产品要记住一般性的代码偏好，就要先解决写入覆盖。对已经入库的证据，还有另一个独立问题：旧版英文回放在同一批 438 题上，369 题找全了金标会话，但只有 203 题从每个金标会话交付了带标注的首选消息。后一个数字来自旧 Python 实验，衡量消息标注覆盖，不能当作 V2 的回答正确率。[本轮源码与实测](project-baseline.md) · [旧实验原始结果](../reassessment-2026-11/longmemeval-results.json)

## 对 bmem 的实验顺序

以下是基于调研提出的优先级。它没有改变既有规格。四组实验可以共用一份按时间排列、带授权范围和原句标注的中英文任务集；先用合成材料和公开基准，再独立检验获准的真实工作任务。在写入阶段隐藏未来问题和金标答案。按同一根来源与任务族分组做时间留出，防止两个助手的转述被分到开发集和留出集两边。[当前实现](project-baseline.md) · [TimlMemBench 作者协议](https://github.com/lyirs/TimlMemBench/blob/447b195344a2feaf995176446379e60632831f94/docs/evaluation.md)

| 顺序 | 如何比较 | 看到什么结果才改变设计 |
|---|---|---|
| 1 · 写入与纠正 | 从同一组轨迹标出必记、可忽略、不可写、应保留的旧维度。覆盖明示长期意图、临时要求、否定、相同话语的转述、独立佐证、迟到更新和项目例外。比较当前声明／普通事件入口与带证据片段的候选提炼；只在相同入口内比较策略。 | 分开报正确生效的必记项／全部必记项、误升为长期事实的数量、出处或范围错误、迟到旧值复活。若记录已到而事实未生效，先改提炼或裁定。高风险误写、事实漏记及正确的 `pending` 分开报告。 |
| 2 · 证据召回与交付 | 在相同授权语料、总候选上限、读者和阅读 token 下，对照精确／词法、向量、两路并集。固定候选后，单独比较命中句与补充相邻动作、结果。再加关闭记忆和直接提供标注证据两组，分开观察能否利用证据。 | 同时报来源全覆盖、送入上下文的证据充分率、拒答与错误注入、配对任务成败。标注证据有效而自动组失败时，先定位损失发生在召回还是组包。仅在多跳题持续失分且有明确关系金标时增加图候选。 |
| 3 · 淘汰与恢复 | 从相同的可读快照分别做冷却、条件到期、纠正、撤销单个助手读取权、来源撤回和明确要求擦除。每项保留有权读者与应可读的邻项，再单独跑一条串行历史检验操作组合。每次先查目标记录及对照项，再查摘要、索引、队列、普通读取、授权历史读取及旧备份恢复预览。 | 按动作记录仍可读的禁止项、误删合法项、重新生成后复现、撤回传播时长及重建量。备份只验证到预览时，结论写到预览；第三方旧上下文和实际恢复另计。 |
| 4 · 收益与持续优化 | 对同一宿主与任务，配对开关记忆，并加入等量无关片段、标注证据两个对照；从少量证据逐步增加预算，计入提炼、嵌入、重排与后台归纳费用。使用独立任务测试或盲评，明确记忆带来反向影响的题。 | 同时报新增成功、原来成功现失败、按任务分组的不确定区间、写入至可用延迟、查询 p95、每个成功任务成本。改动先在冻结集和新时间段比较，影子回放能测候选变化，真实任务收益要在获准使用的宿主上另验。 |

最便宜的起点是第一组，先约定哪些类型要覆盖，再区分“属于目标范围却 pending”“有歧义而正确 pending”和“本版未支持”。从项目现有入口即可复现，结果能决定应先投入事实裁定，还是进入检索实验。上述开源框架可以充当某一环节的对手；现有证据尚不足以支持替换本地权威存储、启用全量对话留存，或采用全局统一的衰减周期。

## Codex 与 Claude Code 的交叉评议

开源源码、论文与本地实现由 Codex 分头核对。Claude Code 在独立临时会话中做了两轮方法评议，只收到公开研究问题和反证摘要。其角色是质疑方案，网页、源码、数据的核验见各分册。以下记录实际改变判断的三点。

| 首轮意见 | 带回讨论的反例 | 二轮后的处理 |
|---|---|---|
| 全量入库代价高，优先抽取；同时担心日后无原文可复核。 | AWS 接口能跳过短期事件持久化；精确键值任务又显示按需读原文的价值。部分来源可在源端按版本回读。 | 按来源选择留存层级，公开记录何时只能核对片段、何时能回源。源端可得性与额外本机副本成本仍需各自实测。 |
| 比较向量、知识图、混合和查询路由。 | 这个对照漏掉了便宜的精确／词法检索，也混入不同阅读预算。 | 把精确／词法加入基线，并固定阅读预算。编排实验时将“原文或抽取事实”与“用什么检索器”分成两个变量。 |
| 把引用当弱标签，再用任务成功作为较强信号。 | 错误证据也可能碰上成功任务；评分只看回答还会遗漏已经送到模型的越界内容。 | 分开检查证据、回答和独立任务结果，用配对干预估计收益。第三方副本的擦除以及无回执宿主的实际使用均保留观测边界。 |

**证据范围。** 本轮是定向工程调研，逐册记录检索词、截止日期、版本及主要局限。开源关注度来自当日 GitHub 快照。可复核的新增实测包括一项开源排序函数、公开双语数据的字段统计和 V2 合成用例；未在统一语料和硬件上部署各系统，也未重跑论文模型。11 月 19 日已冻结的架构与回放保留原版。[旧版冻结清单](../../docs/v2/research.sha256)
